# 低矮地表装饰：蕨草 + 三颗碎石

两件真实Poly Haven源模型的固定光照导出，与v111保持同一55°正交、原太阳方向和每米比例。只用于障碍外围的少量地面细节，不增加碰撞，也不替代角色/敌人/掉落物的视觉层。

## 本轮成果

| 模块 | 实际尺寸（宽×深×高） | 精灵PNG | 投影PNG |
| --- | --- | --- | --- |
| fern_low | 0.630×0.653×0.234m | 40×34px | 88×75px |
| pebble_trio | 0.643×0.391×0.120m | 42×27px | 83×64px |

- `exports/`：4张透明RGBA PNG；每件精灵与独立软接触/地面投影共享脚点
- `exports/manifest.json`：来源、固定比例、每层裁框/脚点、视觉放置包络、绘制层契约及哈希
- `source/ground-dressing.blend`：打包纹理的派生源，2件模块共4个网格部分；各模块均规范化到自身零脚点
- `source/raw-renders/`：本轮未经后处理的4张渲染原图
- `qa/sparse-assembly.png`：真实模块按实际1:1源像素比例技术拼装，不是原生游戏截图
- `qa/sparse-assembly-marked.png`：标出5处稀疏固定摆放
- `qa/module-inspection.png`：同一真实PNG的1:1尺寸与明确标注的6倍检查放大图
- `qa/verification.json`、`qa/package-sha256.json`：验证与备份完整性

只执行一次确认后的渲染批次：2件×精灵/投影，共4次必要图层渲染，没有随机变体、额外试渲染或资源下载。没有读取待批角色包，没有修改冻结v108/v111。

## 最小接入契约

1. 所有PNG使用 `centered=false`，局部offset为 `-foot_local_pixel`。同件精灵与投影父节点用同一实例脚点，完整帧脚点均为 `[640,360]`
2. 每米横向47.4074074源像素，地面纵向38.8338747源像素。源像素运行模式下保持1:1；接入原0.65相机时，纹理与offset一起乘 `1/0.65`，不要重复换算
3. 绘制顺序：地面 → 地面投影 → 这两件装饰 → 角色、敌人、掉落物及立体障碍。装饰不得参与前景遮挡或角色Y-sort前景盖层
4. 不创建碰撞体、导航障碍或实心tile。manifest中的视觉包络只用于规划间距，不是碰撞多边形
5. 只允许固定方向/比例的XY平移。不得随机旋转、镜像或翻转已经烘焙的受光和投影
6. 只放在真实障碍外沿。入口、主路线、怪群活动区与掉落物落点留白；不铺满草叶，不加科技发光

示例只用了3处蕨草、2处碎石组，详见 `qa/example-layout.json`。这些放置包络与v111既有4块碰撞区及示例主路线留白区均无交叠，彼此也无交叠。这是位置规划检查，不是新物理行为或当前主游戏整合测试。

## 阴影与视觉限制

- 仅目标模块参与自身图层渲染，不含邻居、旧地面颜色或整场景遮挡
- 继承原太阳与天光，投影接收面为水平z=0；模型自阴影/材质受光已经烘焙
- 投影使用与v111同类Cycles中性影子捕捉近似。合成器原有0.008 alpha底值处理保留；导出后只把RGB精确归零，alpha与原始渲染逐像素相同，没有追加阈值或抹掉弱半影
- 不是动态光照，不产生模块对其它物件的互投影，不模拟不同地面的彩色间接反射；重叠投影仍可能过暗
- 蕨草在实际比例下刻意较小。6倍图仅供检查，不能据此放大生产素材
- 原生地图摆放、战斗与掉落物可读性仍需整合方检查，本包不冒称已完成

## 复现

派生源按模块局部零点存放，不是两件叠放使用。渲染脚本会明确只启用目标模块。

```sh
# 已完成的批次有保护标记，禁止无意中重复渲染
blender --background --disable-autoexec --threads 4 --python source/build_and_render.py

# 可安全重复：保留原始像素，从raw-renders重新生成导出与技术核对图
/usr/bin/python3 source/finalize.py
```

渲染使用既有Blender 4.3.2/Cycles CPU，256最大采样、无降噪；技术合成使用Pillow、NumPy和GDAL/GEOS。技术拼装脚本只读既有v111地面/模块作为比例参照。源与许可见 `SOURCES.md`。
