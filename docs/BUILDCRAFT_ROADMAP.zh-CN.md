# 构筑内容路线：从词缀研究到可玩的闭环

基线：v0.4 / `164e1dc`；审计日期：2026-10-02。下列顺序按现有执行器和依赖安排，不是对 PoE 内容全量复刻或交付日期的承诺。名称、数值、图形与布局采用本项目原创设计。

## v0.4审计基线事实与缺口

- 已有 181 节点原创树、12 珠宝孔、共享天赋机制；普通珠宝是真实例。装备仍为 9 件固定目录，UI、背包与存档直接依赖目录 ID。
- 已有五类伤害分量、事件标签、逐分量 increased / more、命中时抗性与施放快照。不存在局部武器基础伤害阶段、攻击/法术点伤效用、暴击、持续伤害或完整异常系统。
- 已有母/子投射物、一次返回、自然结束爆炸与谱系限额；技能大部分参数仍写在协调器中，没有技能辅助链接或通用技能编译。
- 已有魔力、技能冷却、护盾与波次成长；攻速只改变普通射击，不等于施法速度或冷却回复。
- 已有原始怪/后代奖励隔离。没有随机装备、制作通货、消耗品经济、地图风险/回报或关卡完成循环。
- 1,200 条普通显式词缀档是研究范围，不是 1,200 个可执行机制。36 项映射包含大量明确未实现的语义，不能把本地、全局、攻击、法术、百分比、每秒数值混用。

## M1 / v0.5：装备掉落闭环（已实现）

先实现小而完整的运行时词缀集，并与独立视觉基础升级一起验收。

- 6 个原创底材，保留武器/护甲/饰品三槽和全部 9 件固定机制/示例装备
- 普通、魔法、稀有装备；独立实例 ID，物品等级与三个档位；前后缀数量上限、族排斥、权重与合法值域
- 12 类可执行适配：生命、魔力、原创全局护盾加值；法术/火/冰/电/攻击元素/投射物伤害；全局普通攻击频率、移动和魔力回复百分比
- 部分是源语义适配，部分是显式标注的原创类比。尤其不把百分比攻速直接加到每秒次数，也不将局部护盾当全局 PoE 等价机制
- 原始怪死亡触发随机装备奖励；后代、演示、取消、重复死亡无奖励；满仓不覆盖任何已有物品
- 装备详情显示稀有度、物品等级、前后缀、档位、掷值和实际作用；生成装备可在游戏内二次确认后丢弃，固定示例保留
- v3→v4 先保存原字节备份，失败不覆盖；未知机制/畸形/重复实例拒绝整份加载

验收：多种等级与稀有度成千次随机生成合法；每族/档可达；固定种子可复现；所有词缀穿脱反映在真实属性/伤害；同一实例只有一个位置；保存往返不重掷；所有拥有物品可回包；满仓/备份冲突/旧版升级零丢失；怪物奖励与旧战斗回归全部通过。Windows 导出检查与 Windows 实机测试分别报告。

## M2 / v0.6：有取舍的技能辅助组合（已实现）

依赖 M1；先统一技能数据和每技能施放编译结果，再扩内容。

- 两个辅助槽按技能 ID 绑定，换快捷栏位置不会错绑
- 起步仅龙卷、飞弹、冰霜三种投射物技能；两个原创辅助：增加初始投射物并降低单次伤害；增加单次伤害并提高魔力成本
- 支持资格按技能能力检查，伤害作用域按每次事件标签检查；箭体不把投射物增伤传给独立爆炸
- 同一编译结果供执行与预览；完整弹幕容量检查成功才扣费；失败不发射、不扣魔力/冷却

验收：重复/不兼容辅助原子拒绝；顺序无关；无跨技能泄漏；母箭增加不重复增加子箭；组合成本一致；飞行中换装不改变旧快照；最大容量/死亡/重置无额外触发；保存与切槽保持绑定。

## M3a / v0.7：分类点伤基础组装（已实现）

已完成固定点数的攻击物理/火和法术冰/电语义适配；新法器自然词池独立，旧全局基伤保持。先建立基础系数与附加效用，再推进真正的武器本地阶段，避免重解释旧装备。详见 TYPED_DAMAGE 与 TYPED_AFFIXES。

## 用户优先插入 / v0.8：开阔视距与百怪（已发布）

扩大真实世界可视面积，保持UI与碰撞单位；常规怪数上限100、渐进批量生成、F7真实百怪试验；保守空间候选索引与原扫描逐事件差分。验收涵盖同屏实际对象、相机/鼠标往返、720p/2K字体、移动/接触伤害、投射物/死亡队列/奖励及性能实测。详见 WIDE_VIEW_DENSITY。

## v0.9：同源可浏览资料与首种特殊珠宝（已发布）

- 每次成果需要可浏览的介绍、图示、来源链接和实际机制说明；资料应从真实目录/执行语义提取，不以外部计划代替实现审计
- 特殊珠宝允许特定未连通节点配置是已提出的功能方向；尚未把其他会话的 A–G 分类、固定半径或点数规则当作确定需求
- 先统一分配、移除、替换、读档的合法性分析，再定义一个有正常获得方式的原创珠宝；逐节点授予不应无意开放无限向外延伸或互相供能
- v0.8已完成视距；v0.9限定为离线同源图鉴与寻枝晶玉一类闭环，规则详见SPECIAL_JEWELS，不加入圆环/星团/永恒或制作地图

## M3b：真正武器本地阶段、元素防御与异常

v0.10已完成事务内合并刷新/保存；v0.11交付有限火系防御遭遇；v0.12按批准参考完成手绘魔法手札。v0.13接入一把可获得的本地物理武器和两种本地前缀，保留旧B并独立加入W，完成真实技能与机会成本预算。详见FIRE_DEFENSES、GRIMOIRE_UI与LOCAL_WEAPON_DAMAGE。其余下列语义按依赖拆小版本，不承诺全量复刻或具体版本日期。

- 先分开武器本地结算、攻击基础、法术基础、加点伤害效用，然后才开放对应词缀
- 玩家与敌方明确物理和元素防御；抗性/上限/穿透分别建模，不能用一个无类型防御代替
- 先做一个完整异常（例如冰缓），明确应用阈值、强度、时长、覆盖/叠加/免疫及 Boss 限制，再扩燃烧/感电
- 暴击、DoT、吸取各自分阶段；不借用 hit 的倍率或奖励路径伪造

验收：同种词缀只影响正确阶段/类型；独立爆炸不误继承攻击点伤；同种状态并发与免疫确定；DoT 不误触发命中；资源回复与死亡结算有上限；完整伤害追踪可解释。

## M4：轻量制作和回收

- 在合法实例、完整存档和词缀作用域稳定后添加原创材料
- 首批提供重掷、补充空词缀、回收三种有界操作；预览花费/结果范围，确认后原子扣料
- 不加入交易市场或付费资源；不把“随机制作”等同高质量保证

验收：重复点击/中断/读档不会复制材料；失败不吞物品；前后缀与族约束一直有效；回收/支出分布和掉落节奏可回归测试。

## M5：有风险回报的地图遭遇

- 原创小地图/遭遇模板、完成目标、Boss 与奖励结算；保留现有竞技场用于对照测试
- 地图词缀必须真正改变敌人或环境，并对应可见奖励；先选择/预览，再进入
- 数个短流程验证远程、范围、单体、防御构筑的不同取舍，不用纯粹堆血量代替内容

验收：入口/死亡/离开/完成的状态机明确；重复完成不给重复奖励；不同地图词缀确实影响战斗；至少三种构筑能完成合理难度，并展示长短板。

## 每个检查点的完成规则

定义支持/未支持清单 → 原创数据/代码 → 纯模型测试 → 真实场景与失败路径 → 旧存档/回归 → 图形检查 → 提交 → 远端逐文件核验。已冻结版本独立保留，不以未测试开发树覆盖发布包。常规可逆内容与平衡自行迭代；重大玩法方向、2D→3D、收费资源、公开发布或破坏性存档调整需要明确决策。
