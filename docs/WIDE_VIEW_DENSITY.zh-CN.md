# 开阔视距与真实百怪

版本：v0.8。起点是「怪物占屏太大，希望一屏容纳接近100只怪」的实际反馈。数字是本游戏的工程设计，不是对其他ARPG视距或性能的测量。

## 视野怎样变化

| 层 | v0.7 | v0.8 |
|---|---:|---:|
| 逻辑视口 | 1280×720 | 1280×720 |
| HUD之间的画面区域 | 1196×462 | 1196×462 |
| 可战斗世界尺寸 | 1196×462 | 1840×710.769 |
| 原生相机缩放 | 1 | 0.65 |
| 同屏世界面积 | 1 | 2.366864 |
| 场上怪物上限 | 55 | 100 |
| 常规每批生成 | 1～3 | 2～5 |

`WorldView`定义唯一真实战场矩形。`WorldCamera`在HUD创建前设置，世界中的角色、怪物、投射物与区域技能一起投影。CanvasLayer内的HUD保持原有位置和UI/字号设置，没有跟随世界缩小。

相机不是把单位判定缩小：人物半径仍为15，怪物半径仍读原目录；移动、击退、冲刺距离、射程、范围和伤害继续用原世界单位。这也意味着同一个技能在更宽的画面里覆盖比例较小，世界移动在画面里的距离相应缩短。

`from_reference`只转换旧试验场的布局坐标，不改变单位尺寸。鼠标使用原生`get_global_mouse_position()`逆变换；测试另外验证正反坐标映射，避免宽视野下射向错误位置。

## 百怪是真实战斗对象

F7的「100怪视距试验」以目录创建100个实际敌人，有唯一身份、生命、护盾、攻速、移速、碰撞半径、机制快照和死亡结算。它们包含普通/魔法/稀有三类与一个关卡首领。关闭面板后原AI开始移动，玩家可以攻击、受击和死亡。

试验场仅关闭成长奖励，并暂停自动普攻以便观察；没有缩小碰撞、替换装饰点或虚报数量。HUD场上数读取实际数组。试验开始后死亡或后代填位会使构成变化，100是初始数量与硬上限，并非永不下降的假计数。

常规挑战同样采用100上限，每批`min(5, 2 + floor(wave / 4))`只，间隔仍为`max(0.42, 1.45 - wave × 0.07)`秒。原始怪掉落、每五波首领和成长规则不变。增加数量会提高战斗压力；没有把同屏100视为每一波必须常驻100。

## 生成与性能边界

- 四边生成位置按新世界矩形计算，保留原世界单位边距与接近玩家时翻转到对侧的规则
- 满100只时拒绝新根怪；先清理死亡对象，待生成后代按FIFO优先占用空位，然后才补普通怪
- 64待生成队列、每根3代/12后代/每次死亡6子怪预算继续有效，不随场上容量一起放大
- 投射物仍最多180，独立视觉反馈仍最多96；没有扩无界对象池
- 空间索引只筛候选，精确线段圆交、相撞顺序、返回/分裂/结束时机、伤害快照继续由旧执行器决定
- 调度队列仅在证明次序严格且没有新增工作时复用排序，近似时间歧义或重复身份继续逐次排序；不改变历史事件优先级
- 敌人分离力查询按原数组索引顺序，移动并钳制后立即更新空间索引，保留旧逐个原地更新语义
- 极密集聚堆会退化成完整候选扫描，这是为了正确性；不通过漏判换性能

具体边界、差分样本与候选统计见[空间候选索引](SPATIAL_COLLISION.zh-CN.md)。候选减少比例不是整帧加速比例；云端Linux软件渲染计时不能当作Windows/显卡帧率保证。

## 信息可读性

角色本体随真实相机变小，HUD/字体不变。怪物全名按首领、稀有、悬停等优先级选择，最多8条并避免名字互相重叠；普通满血怪物不铺满血条。必要的稀有度、护盾、受击与减速提示保留。实际显示与验证说明见[视觉系统](VISUAL_SYSTEM.zh-CN.md)。

## 原生量测结果

在相同装备、朝向与关闭动态效果的条件下，分别真实渲染前后两版，没有用缩放乘法生成量测图：

| 本体（不含独立阴影/文字） | 720p原高度→新高度 | 2K原高度→新高度 |
|---|---:|---:|
| 人物及持有法杖 | 46→31px | 93→60px |
| 巡游体 | 34→22px | 68→44px |
| 掠行体 | 32→20px | 64→42px |
| 重壳体 | 52→34px | 106→68px |
| 裂隙守卫 | 72→46px | 144→94px |

实际主场景逐项核对77个UI控件的矩形/变换和40个字体节点，两档分辨率均无变化。半透明控件背后的世界改变，不能据此声称UI位图逐像素一致。名字名义字号保持12px，亚像素位置可产生1～2px栅格边界差异。

720p与2K试验中100只实际AI均移动；真实飞弹施放后记录2次击杀、98存活和5条伤害记录。持续4秒的聚堆截图只在专用QA夹具中保护玩家，敌人仍使用目录数值；这项保护不写入游戏模式。低特效另有投射物/命中对照。

最大UI110%/字体120%的波次与实时数量文本需要239px，容器可用270px。此设置在720p沿用旧响应式规则隐藏右下操作区，快捷键仍可用，没有新增视距相关布局变化。

## CPU压力实测与剩余边界

在共享Linux AMD EPYC 9V74（9逻辑处理器）、Godot4.6.3无界面debug引擎中，对同一100怪/180弹夹具比较原全扫描与逐次排序，及空间索引与安全排序复用。统计完整tick，包含AI、碰撞、伤害和反馈更新，不含渲染/HUD、准备或复制夹具。为持续维持负载，计时夹具提高生命并保护玩家；与上面的原目录实战截图分别记录。

| 场景 | 历史平均 | 优化平均 | 优化p95 |
|---|---:|---:|---:|
| 稳态无命中（120帧） | 72.61ms | 4.48ms | 5.78ms |
| 混合366次命中（120帧） | 73.21ms | 6.06ms | 7.97ms |
| 聚堆344次命中（120帧） | 77.30ms | 11.18ms | 15.52ms |
| 每帧180同刻命中（60帧） | 87.56ms | 56.12ms | 67.47ms |

四类完整战斗状态逐值相等。前三类将120帧排序次数从21600降至120；极端爆发含数值不等但近似相等的命中时刻，为保留历史顺序仍回退到10800次排序。这个压力边界依然较慢，不能用前三行平均值宣称所有情况60FPS。共享机器负载、debug引擎和未计渲染也限制计时的外推。

原始字段和计数见[基准数据](benchmarks/v0.8-density.json)，可用同一脚本与固定种子复测。

## 验收入口

- `tests/spatial_collision_test.gd`：原扫描/索引事件与投射物深比较、边界/重复引用/全聚堆、100×180候选对照
- `tests/density_integration_test.gd`：真实100/第101拒绝、自然生成、真实移动/受击/掉落抑制与恢复、逐帧分离力差分
- `tests/projectile_schedule_test.gd`：排序复用与历史逐次排序的生命周期/歧义边界差分
- `tests/density_benchmark.gd`：独立记录CPU计时与候选，不设跨机器固定帧率承诺
- 原`monster_integration_test`继续检查死亡FIFO、队列优先与上限；所有伤害、存档、装备、技能辅助回归保留
- Linux原生渲染检查宽视野、百怪、鼠标与720p/2K；Windows包另验PE与PCK，Windows原生仍需单独实测

本版存档仍为v6，已有物品/词缀/辅助/天赋数据不迁移、不重掷。
