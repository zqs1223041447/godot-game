# Passive tree Simplified Chinese display mapping

This change adds Chinese display text to the canonical passive tree UI while retaining the pinned English source as the only input to the parser and game logic. The map is pinned to source version `3.29.1`, SHA-256 `7e9f755e33152129ebf36c2ebdad639c527e4ad70d274b1fefb860f30ca01122`.

## Coverage

`data/passive_source/localization_zh_CN.json` is generated by `tools/passive_import/build_source_tree_zh.py`. It keys node names by their original source IDs and effect translations by the complete exact English source string. It does not modify source node data, stat strings, IDs, mastery IDs, graph coordinates, edges, save data, or parsing rules.

The current map reports:

- 3,390 source node IDs, including 3,389 non-empty source names and 1,910 unique names.
- 2,974 exact effect strings covering 6,981 occurrences across nodes and mastery choices.
- 1,837 mastery options across 353 mastery nodes.
- 95 multiline effect entries, each with a reviewed Chinese translation.
- 7 class labels and 37 ascendancy labels.
- 2,387 standard tree positions, 60 jewel socket names, and 42 expansion-jewel nodes.
- No untranslated mapped names or effect strings. The one source node with an empty name remains empty because it has no player-facing source name.

The source contains `reminderText` on 802 node records (1,015 text entries). The canonical passive tree panel does not display these fields; this is tracked separately in the coverage report and they are not part of the visible tree copy.

## Wording contract

The displayed modifier terms preserve their game meanings:

| Source modifier | Chinese display | Meaning |
| --- | --- | --- |
| `increased` | 提高 | Additive within the same modifier group |
| `reduced` | 降低 | Additive within the same modifier group |
| `more` | 额外提高 | Independent multiplicative modifier |
| `less` | 额外降低 | Independent multiplicative modifier |
| `+X% to … Multiplier` | 倍率 +X% | Additive percentage points to that multiplier |

Values, signs, conditions, durations, and per-item/per-level qualifiers stay with their source effect. The game glossary appears in the node detail tooltip. No English modifier term is added to the game text.

`Flask Charge(s)` is shown as `药剂充能`; ordinary endurance/frenzy/power charges keep their distinct Chinese names. `Power` means `威力` in Warcry rules and is not confused with `Power Charge` (`暴击球`). Projectile `fire` is translated as `发射`, and chance-to-ailment rows explicitly identify the enemy receiving the ailment.

## Implementation labels

The translation JSON contains display text only. `SourceTreeLocalization.line_status()` calls the current `SourceTreeRuntime.line_effect()` using the current save/schema version, then requires every parsed grant to have an explicit consumer entry in `STAT_CONSUMER_GROUPS`. Each consumer group lists code paths and exact source markers in `code_checks`; the exhaustive localization test checks those files and markers, so a parser match or an evidence string alone cannot make a stat appear implemented. A parser match without a documented consumer, any unsupported format, and any unknown stat remain marked `（暂未实装）`. The status is resolved per exact source stat row, so a supported mastery choice or sibling row cannot hide an unsupported row.

The currently supported fire damage-over-time multiplier rows at node IDs `4713`, `5916`, `13559`, `31462`, `54396`, `2550`, `11924`, and `29049` stay unmarked. Mastery effect `36313` is partial: the supported fire multiplier row is unmarked, while `50% increased Ignite Duration on you` is marked. `Deadly Draw` (`48823`) keeps its bow damage-over-time and faster-damaging-ailments rows separate, each with its own current status.

The `Damaging Ailments deal damage X% faster` display uses the broad wording `伤害型异常状态的伤害结算加快X%`. The original authoring baseline was v53/schema32, where the parser did not recognize it. In the integrated v57 build the existing schema34 save uses execution vocabulary33, so the implemented faster-burn rows are unmarked. The `damaging_ailments_faster` consumer group is already registered against the schema 33 code path: `FASTER_BURN_PATTERNS` → `source_tree_runtime.gd` → `burn_rules.gd`. The test is schema-aware: on schema 32 it requires the unsupported marker; on schema 33 it requires parser support, a matching consumer, and no marker. On the v54/schema 33 implementation this stat is consumed by the burn timing rules. `Deadly Draw` (`48823`) is partial there because its faster-ailment row is supported while its Bow DoT row remains unsupported. The translation stays general and does not narrow the source to fire damage.

## UI wiring and audit

The canonical panel now uses the mapping for class and partition pickers, positioned node names, node effects, mastery options, details, and hover tooltips. It keeps original IDs and English source names only as non-displayed search aliases. Jewel socket nodes use their mapped Chinese names. The original translation commits contain no font, layout, font size, or art changes. The v57 integration expands the same recorded font subset to cover all mapped text, retaining old glyph outlines and layout metrics; no font fallback, size, layout or art changes are introduced.

`tests/source_tree_localization_test.gd` checks source hash and unchanged source identity, every mapped node and effect occurrence, exact numeric/sign token preservation, no ASCII residue in mapped player-facing text, distinct modifier terms, the consumer code-path manifest, per-row implementation markers, the named fire multiplier and mastery cases, and the canonical panel/partition UI. It also checks the complete flask-charge inventory and all chance-to-ailment rows for explicit enemy targets. Font coverage for mapped text and passive panel copy is recorded in [passive-tree-zh-CN-font-gaps.md](qa/passive-tree-zh-CN-font-gaps.md). It lists all missing glyphs from the existing `assets/fonts/arena_sans.otf`; the UI font is unchanged.

## v57 integration on current gameplay

The original four LUNA commits through `bfbc009167c1ce2b0fece3365d3ad1c2e723e5be` were merged onto published v56 `386f465a7dd929836c3def3091a58939a90f1e36`; the final 15-row semantic fix `8b4f627c4ba1f24f14d6bc2e81a9abd56a4cc638` was cherry-picked with its original author. The source IDs, English formulas, graph, schema34 and execution policy33 remain unchanged.

`export_presets.cfg` explicitly includes the sole runtime localization JSON and continues to exclude the other three research source files. The package verifier rejects any other file under `data/passive_source/` and compares the exported mapping to frozen source bytes.

Full final font collection against the shipped v56 font adds 582 Chinese glyphs: 1073→1655 codepoints, same verified Noto CJK source. All previous glyph outlines/advances and font-wide metrics remain identical. This covers the complete map, not only the last wording patch.

The canonical panel's existing partition/start refresh flags were repaired so browsing actually changes its graph. Search accepts Chinese display names, original English aliases and numeric IDs. The existing unsupported-mastery dropdown stays disabled; only fully implemented choices can be allocated. Offline F8 passive entries use a separate display projection exported from the same Godot localization/status resolver, while authoritative `catalog.source_tree` keeps English source and execution results.

Focused integration results and retained fixture failures are recorded in [v57 integration QA](qa/v057-integration/README.md) and [model compatibility QA](qa/v057-compatibility/README.zh-CN.md). The work does not rerun historical battle suites or add a gameplay mechanic.
