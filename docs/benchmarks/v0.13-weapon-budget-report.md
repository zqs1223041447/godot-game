# v0.13 local weapon budget: production acceptance

Accepted configuration: `ashwood_bow`, normal 2×3 footprint, local physical base **P=4**, two competing local **prefixes**. `whetstone_edge` tiers are 1–2 / 3–4 / 5–6 points; `tempered_edge` tiers are 10–15% / 16–22% / 23–30%. The production maximum is **W=13**. Magic permits one prefix, so it cannot combine both local families. There is no local attack-speed affix. All values and tiers are original game balancing, not copied PoE data.

## Result

- **Pass:** 340,692 focused checks, zero failures, 92,580 production candidate/context/support/target evaluations. The normal no-report suite run prints 340,691 checks; explicit artifact writing adds one destination-open check
- All **288** current-environment maxima rows match the independent historical prediction. Old-weapon ceilings remain unchanged; largest absolute old-output difference is `2.27e-13` and largest new-prediction difference is `2.27e-13` (floating-point rounding)
- Current maximum advantage across all rarities is **+17.587302%**; maximum rare advantage is **+16.263696%**. Both pass the 25% gate across all four support choices
- Rare tier-3 isolated basic hit: **36.6000 old → 36.5800 new**. Tornado parent: **38.0400 old → 38.0200 new**. This is near parity, with the new bow shifting part of the damage into physical damage
- Same-item local-prefix off/on comparisons preserve ordinary character stats, attack rate, every spell packet and every independent secondary packet; local attack packets increase. A normal bow also preserves spell/secondary packets compared with unequipping it
- Measured targeted replay runtime: 93.8 seconds with Godot 4.6.3. This report covers the budget test; scene lifecycle, save, UI, RNG and aggregate validation belong to their separate tests

## Independent evidence and scope

The original audit used the genuine v0.12 compiler and resolver from commit `1f948911e20081edd4cd7adf96203631d45a6726`, inserting proposed local W into attack packets only after historical compilation. Its 22,899-evaluation no-support result, fixed-weapon result and context sections remain exactly equal as parsed JSON to the original audit. The archived harness now also replays volley, focus and both together through that same old compiler: **91,596** current-matrix evaluations including fixed weapons, plus **840** separate future-stress evaluations. It refuses non-schema8 source trees.

The historical snapshot’s 104 tracked script/data/project files were compared byte-for-byte with that commit; all matched. The expanded prediction ran in a disposable copy, leaving the immutable snapshot untouched. The hash manifest records each historical file, original audit hashes, the expanded harness/result hashes and the production replay inputs. A source-only portable checkout also passed Godot script parsing without import/editor work.

The independent production test enumerates and validates real catalog instances, installs ownership, equips them through BuildState, retains the required passive root, and validates the complete persistent build. It obtains the raw seven-key weapon profile from `get_combat_snapshot()`. SkillCompiler/CombatData and DamageResolver calculate every hit. The production test contains no duplicate damage or W formula and never inserts weapon damage itself.

The matrix is:

- Item levels 1, 8, 16 and 30; normal, magic and rare; all legal maximum-count, highest-unlocked-tier, maximum-tick combinations
- Historical bases `cinder_reed`, `gale_spindle`, `runewood_focus`, compared with `ashwood_bow` in its actual `local_weapon` pool
- Candidates per item level: normal **3 old / 1 new**, magic **80 / 30**, rare **640 / 200**
- Supports: none, volley, focus, both for tornado/bolt/frost. Other skills retain their legal empty support lists
- Contexts: isolated; the actually equipped detonation charm (+20% global/+30% elemental); labelled sensitivity input (+50% each global/projectile/elemental). The last is a stress input, not a claim about a specific reachable talent allocation
- Targets: zero resistance and 25% fire resistance. No armor/shield overlap or unlisted mitigation is folded in
- Skills: basic, tornado parent/child, bolt, frost, nova, meteor, all five chain hits, and one independent secondary explosion; fixed ember wand, prism bow and swift blade are independently replayed
- Each metric is maximized independently and records its own legal witness. A table row does **not** describe one item that simultaneously maximizes every skill, attack rate and secondary explosion

Every eligible modifier is nonnegative, so a lower-count, lower-tier or lower-tick subset cannot exceed the enumerated maximum-count/tier/tick ceilings. This proves ceilings within these legal pools and recipes, not roll frequencies, average loot strength or all future game content.

Without supports, the fixed prism remains **477.4000** carrier potential versus **353.5860** on the tier-3 rare new bow, because the prism has five parents and fifteen children while the random bow has three parents and nine children. The two bows cannot be equipped together. Ordinary beatlink affects ordinary-attack rate; the new local prefixes do not affect rate, projectile count, mana or cooldown.

**Carrier potential is not actual DPS.** It sums one hit from every emitted carrier and assumes those hits connect. It omits target geometry, repeated/piercing contacts, returns, secondary explosions, cooldowns, mana sustainability, uptime and encounter defenses beyond the listed resistance. Basic × attack rate is only a controlled ideal throughput proxy; it is also not actual encounter DPS.

## Current gate and future-defense warning

The largest current ratio is on a tier-2 magic tornado under the labelled amplification sensitivity input against the 25% fire-resistant target: **1.175873**. The largest rare ratio is tier-1 tornado in the isolated context against that target: **1.162637**. The same support applied on each side preserves these ratios; the full support-expanded matrix independently confirms this.

A separate synthetic target with **75% fire resistance**, isolated tier-3 rare and no supports, gives old tornado parent **24.3780** versus new **30.5680**, ratio **1.253917467** (**+25.391747%**). This lies **outside today's 25% gate and target set**. It is recorded as a future-balance warning, not a current pass claim. Re-run and reconsider this budget when adding such defenses.

## Reproduction

From the repository root, run only the production budget test with isolated user data. By default the test prints one final summary and writes no artifact. `--progress` adds level/rarity progress lines; `--report` explicitly writes the replay JSON. No editor/import/full-suite run is needed for this focused check.

```bash
budget_xdg="$(mktemp -d)"
mkdir -p "$budget_xdg/data" "$budget_xdg/config" "$budget_xdg/cache"
XDG_DATA_HOME="$budget_xdg/data" XDG_CONFIG_HOME="$budget_xdg/config" XDG_CACHE_HOME="$budget_xdg/cache" \
  godot --headless --path "$PWD" --script res://tests/local_weapon_budget_test.gd -- \
  --report="$PWD/docs/benchmarks/v0.13-weapon-budget-replay.json"
```

To regenerate the independent prediction, use a separate clean copy of the historical commit. Never execute the prediction harness against current production sources. The following writes the new prediction only into a disposable directory and compares parsed JSON with the archive:

```bash
budget_repo="$PWD"
budget_v012="$(mktemp -d)"
budget_reference_xdg="$(mktemp -d)"
git archive 1f948911e20081edd4cd7adf96203631d45a6726 | tar -x -C "$budget_v012"
mkdir -p "$budget_reference_xdg/data" "$budget_reference_xdg/config" "$budget_reference_xdg/cache"
XDG_DATA_HOME="$budget_reference_xdg/data" XDG_CONFIG_HOME="$budget_reference_xdg/config" XDG_CACHE_HOME="$budget_reference_xdg/cache" \
  godot --headless --path "$budget_v012" \
  --script "$budget_repo/docs/benchmarks/v0.13-weapon-budget-prediction.gd" -- \
  --moderate --output="$budget_v012/prediction.json"
python3 - "$budget_v012/prediction.json" "$budget_repo/docs/benchmarks/v0.13-weapon-budget-prediction.json" <<'PY'
import json, sys
with open(sys.argv[1]) as actual, open(sys.argv[2]) as expected:
    assert json.load(actual) == json.load(expected)
print("Historical prediction matches the archive")
PY
```

Use Godot 4.6.3 for exact archived JSON reproduction. Other supported versions can be tested, but should compare numeric values with the production test tolerance rather than require byte-identical floating-point serialization. Any `SCRIPT ERROR:` or `ERROR:` output invalidates a run even if Godot exits zero, as enforced by the repository validator.
