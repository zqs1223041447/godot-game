# v0.4.0 怪物机制设计与验收

## 目标与边界

在现有三种追击怪、波次、天赋星图、投射物/伤害分离架构上增加可组合怪物。普通刷怪只有白、蓝、金；橙色只出现在关卡/特殊地图 Boss 上下文；黑色保留，本版拒绝生成。参考 PoE 的设计语言，名称、美术与具体数值为本项目原创。

本版天赋实际能力为属性型机制（生命、伤害、攻速、移速、护盾与回复等）。先共享这些已经实现的语义，不把尚无执行器的投射物、施法、魔力或未来天赋假装成怪物能力。新增语义必须先添加双方执行器与支持声明，再进入怪物池。

## 单一权威与版本传播

天赋节点保留稳定节点 ID，引用共享机制 ID。机制注册表持有唯一属性定义；角色和怪物均从该定义解析。怪物仅保存机制 ID 和角色平衡系数，不复制天赋数值。树的布局/连线变动与机制语义变动分开：共享机制更新自动影响双方；移除或重命名 ID 要有迁移别名，否则未知机制拒绝整个怪物配置，不能部分失效后继续生成。

共享语义相同：伤害为攻击基础伤害加值，攻速为每秒攻击次数加值，移速为每秒像素加值，护盾先吸收伤害，受击后四秒恢复。角色与怪物的基础值、稀有度倍率、体型及 AI 属于各自模板。魔力相关组合为玩家专用；不静默丢掉其中字段。

运行中怪物在生成时解析一次机制快照，避免版本热改导致生命比例跳变；后续新生成怪物使用最新注册表。存档只保留原 v3 角色构筑，没有缓存怪物数值或战斗状态，旧版升级不需要搬迁波次。

## 五类稀有度

| 类别 | 标识 | 生成与能力 |
| --- | --- | --- |
| 白 | normal | 普通池；无额外天赋机制 |
| 蓝 | magic | 普通池；1 项共享天赋机制；可有模板级死亡生成 |
| 金 | rare | 普通池；2 项共享天赋机制；可有模板级死亡生成 |
| 橙 | boss | 只允许显式 level_boss / map_boss 上下文；专用模板 |
| 黑 | reserved | 仅保留数据与 UI；拒绝随机与显式生成 |

形状保留三种物种区别，外环、名字与文字标签表达稀有度，避免仅靠颜色识别。橙色不是普通怪随机升阶的结果。

## 死亡生成：状态模板图与预算

模板 ID 区分物种和状态。例如裂殖体 A（蓝）死亡后生成普通巡游体 A（白）×2 和掠行体 B（白）×1；普通 A 没有死亡生成词缀，所以 A特殊→A普通不是循环。孵化巨体（金）→裂殖体×2→终端小怪，是合法多阶段、多个分支。

1. 内容校验：明确 child template ID 和数量，拒绝缺失目标、零/负/过量数量、Boss/保留目标、直接自环和间接环；以模板状态建图，不以物种名建图
2. 一次性死亡事务：先置 death_processed，再结算奖励和入队。重复伤害、同帧爆炸、尸体清理、重置都不能重复触发
3. 子怪只采用目标模板的机制与死亡行为，不从母体复制稀有度或生成词缀；显式目标可以再次生成，但受无环图和运行时预算双重约束
4. 运行时限额：根怪后最多 3 代、最多 12 只后代，每次死亡最多 6 子怪，场上最多 100 怪（v0.8，原 v0.4–v0.7 为 55），待生成最多 64 只
5. 全组入队：谱系/队列预算不足时整组取消并记录原因，不生成半组；场上满时保留队列，空位出现后 FIFO 逐只补齐，普通刷怪让位于队列
6. 预算在入队时占用，取消不返还；重置/玩家死亡清空队列，不制造死亡事件。无存活成员与待生成成员的谱系会回收，不无限积累
7. 子怪有出生保护与间隔位置，不在正在结算的 AoE 列表中同步插入，避免同一伤害反复杀穿生成链

## 奖励与演示

根怪只奖励一次经验、有效击杀/补给/珠宝进度。全部后代可计入场上击败数，但无经验、掉落或奖励击杀进度，避免分裂刷取。怪物机制试验场所有对象都无成长奖励，常规挑战恢复后正常发放。F7 可进入、重复演示、查看生成记录并恢复常规挑战；面板打开暂停战斗。

## 验收计划

- 共享机制改值同时影响角色和怪物；树说明不会残留旧数字；已生成怪保持快照
- 正常五类目录；10,000 次随机抽样无橙/黑；Boss 上下文限制和黑色拒绝
- A特殊→A普通、多 B、多阶段 A→B→C 正确；直接/间接环及畸形配置失败
- 同一死亡只处理一次；无奖励后代；一次 AoE 不命中新生后代；尸体重复引用不重复奖励
- 场上满/队列满/谱系代数/总量边界；大时间步；重复死亡、重置、玩家死亡与面板暂停
- 原三种物种、投射物全套、天赋/珠宝/存档 v1/v2/v3 回归；Linux 图形检查；Windows 导出与 PE/PCK 校验（不等同 Windows 实机测试）


## 最终实现与验证记录

- 公共机制目录共 23 包，其中 13 包具备完整怪物执行器；PoE 校准数据只在 `data/passive_balance.json` 定义，怪物模板只有 ID
- 蓝/金/橙模板解析时保存机制 schema、revision 与 policy 版本及数值快照；已有怪物不受运行中调参追溯影响，新怪物读取最新定义
- `set_definition_stats` 仅为内存测试/调参钩子；永久版本改动必须编辑唯一JSON并重跑来源校验与平衡测试
- 玩家总天赋预算与怪物稀有度/模板机制数量限制属于角色平衡层，基础机制语义一致；详见天赋适配文档
- 53,694 项自动断言，怪物模型 266 项、真实场景 87 项均通过。包括10,000次普通池抽样、复制尸体、整组限额、满场FIFO、出生保护和四秒护盾回复边界
- Linux真实窗口检查通过，截图展示实际F7面板、三只终端后代、试验场和已分配的三点通用伤害路径
- 运行包仅包含必要平衡JSON，装备/天赋原始参考盘点不随PCK发行；Windows原生执行尚未验证
