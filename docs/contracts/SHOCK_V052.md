# Shock prototype (v0.52 content branch)

This branch starts at published v0.51 (`d6684d27517e4661abd832d586fcdbb72185929e`). It does not include the withdrawn burn-rate experiment. Focused implementation checkpoint: resource import, policy/runtime, compiler/catalog, strict migration and actual-main gameplay checks pass. Packaging acceptance is pending.

- `shock` / `support:shock` is an explicit support for bolt, nova, chain only. Primary hit damage ×0.80 and mana ×1.20 are prototype balance values. Only a surviving target taking positive actual shield/life loss from a hit with positive mitigated lightning receives shock after settlement.
- Player support grants 2 seconds, 15% increased hit damage taken. Existing shock multiplies each post-resistance/armour hit component once before shield/life settlement. It does not increase damage over time, retroactively amplify the applying hit, stack, propagate, or attach from an independent explosion. Existing shock can amplify that explosion as a subsequent hit.
- Storm skitter grants the same strength for 1 second only from its locked, dodgeable ground warning. Windup 0.7 seconds, radius 65 and recovery 1.6 seconds are retained. Its upfront multiplier changes from 1.6 to 1.4. Other monster admission, rarity and rewards are unchanged.
- Policies are owned by `ShockRules`. `compiled.shock_profile` is detached presentation metadata; the cast snapshot freezes `shock_policy`. Primary roles match actual recipes: projectile for bolt, direct for nova, bounce for chain. No-source compiled values retain the old shape.
- Shock state is ephemeral, per target, and consumes no RNG. Same strength refreshes the latest actual expiry/source. Continuous refresh retains the start of uninterrupted activity; earlier near-ties do not replace newer provenance. Death, restart, map completion and profile switch clear the relevant states.
- Hit queries use the original event timestamp, never the normalized burn clock. Production simulation steps are exactly 1/60 second. One prior interval retains expiry-crossing near-ties; a monotonic read floor rejects discarded history. Complete projectile batches are prevalidated before any hit settlement. Larger forward-only steps remain accepted; arbitrary history playback is not supported.
- Save schema 31 validates schema 30 before a version-only migration and keeps the original raw bytes as a backup. No grant, UID, revision or reward-ordinal change is made. Existing normal gem milestones keep their released ordering. The formal merchant asks 4 calibration shards; isolated test-town supply remains free.

This is this game's initial prototype, not a claim of reproducing another game's exact formula. UI preview and the authoritative skill definition explain the tradeoffs. No Windows hardware performance claim is made.
