# v59 三元素最大抗性

基线 v58 `71f4863fda4b02d1afd17db4cfa958c85139491f`。本批只接通最大火焰、冰冷、闪电抗性的无条件源词汇；受击延迟回复不在本批。

## 本游戏预算

默认最大抗性为75%，本批明确选定安全上限83%。每种元素的当前上限为 `min(0.83, 0.75 + maximum_<element>_resistance_add)`，有效抗性为 `clamp(raw_resistance, 0, current_cap)`。增量是百分点的小数加总，不是原始抗性。原始40%即使当前上限83%仍仅减伤40%；原始75%同样不会凭空变成83%。原始抗性足够时，100点对应元素伤害从25降至17，即相对75%上限少承受32%。这属于本游戏原型平衡，不宣称复刻外部游戏完整规则。

原始源资料的90%提醒保留；它不是本游戏当前安全上限。通用 DamageResolver 的既存90%解析兼容边界也不作为本批新增预算。

## 执行与显示合同

- 执行字段为 `maximum_fire_resistance_add`、`maximum_cold_resistance_add`、`maximum_lightning_resistance_add`。全元素最大抗性句一次展开为三字段，不另保留一个会重复叠加的all字段。
- 命中、火焰燃烧及燃烧状态的有效DPS使用同一权威抗性公式。其后沿原顺序结算命中的护甲/感电与护盾、魔力分担、生命；燃烧不加入护甲或感电命中乘区。
- 最大抗性是当前防御，不冻结到攻击者施放快照。换装、分配或退款只更新以后结算的防御，不改已算伤害或燃烧原始DPS。
- 缺字段或显式数值零沿旧抗性计算及完整伤害返回路径；不为旧正时间片燃烧添加新的通用比率函数链。新增只读显示profile独立返回，不向旧伤害回执添加无用字段。
- `Defense.resistance_profile` 与 `Model.get_resistance_profile()` 返回 `ok/reason/base_cap/safety_cap/raw_resistances/maximum_resistances/effective_resistances`，元素键均为 `fire/cold/lightning`。C页沿原三行读取effective，提示读raw与当前cap，不在UI重算规则。
- 共享规则支持玩家/怪物调用，但自然怪、现有地图元素庇护不新增最大抗性属性。无新队列、随机调用、怪物遍历或攻击暂停。
- schema36先严格校验旧35，保留旧存档原字节备份后仅迁版本；不赠点、不改ID/英文源/图结构/源版本3.29.1。旧35注入新增可分配节点仍拒绝。
