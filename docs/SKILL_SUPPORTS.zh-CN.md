# 技能辅助执行契约（v0.6）

> v0.14 增加贯穿辅助，现有三种可选、仍最多两槽。本文保留两种原始辅助的契约；新规则与v10迁移见[贯穿辅助](PROJECTILE_SUPPORT_EXTENSION.zh-CN.md)。统一查询入口为SupportRegistry。

> v0.7 补充：所有技能的编译结果现在还包含冻结的 packets / compiled_packets 与 compiled_skill_id；工具技能的包为空。所有已编译快照都拒绝再次编译。旧伤害、消耗与辅助规则保留，分类点伤的新阶段以 TYPED_DAMAGE.zh-CN.md 为准。下文保留 v0.6 引入时的接口说明。

本阶段只实现有界的技能辅助编译：每个技能 ID 最多绑定两个辅助，起步仅龙卷射击、奥术飞弹、冰霜脉冲可装配。两个原创辅助全部直接可用；没有宝石物品、掉落、交易、等级、品质、插槽颜色、连线或消耗品经济。

参考范围：[GGG 官方游戏概览](https://www.pathofexile.com/game) 提供“辅助改变技能行为”的设计方向，见既有[构筑路线](BUILDCRAFT_ROADMAP.zh-CN.md)中的研究记录。本项目辅助名称、数值和约束为原创设计，不是 PoE 技能宝石数值或完整机制的复刻。

## 两个辅助与取舍

| 稳定 ID | 名称 | 行为 | 单次投射物命中 | 魔力 |
| --- | --- | --- | --- | --- |
| `volley` | 散束辅助 | 初始投射物 +2 | 总降 20%，即 ×0.80 | ×1.30 |
| `focus` | 凝束辅助 | 不改变数量 | 总增 25%，即 ×1.25 | ×1.20 |

- 两者可同时装配，不能重复装配同一个辅助
- 同时装配时，单次投射物命中倍率为 `0.80 × 1.25 = 1.00`，初始投射物 +2，魔力消耗为原值 `×1.56`
- 总增/总降属于逐分量的独立 `more` 因子，不加入装备/天赋的 `increased` 总和，也不改写角色全局基础伤害
- 冷却不变。普通攻击、新星、冲刺、结界、陨星、连锁闪电不会获得这两个辅助的增伤
- 独立爆炸不受任何一个辅助的伤害倍率影响。返回、自然结束、分裂、碰撞消耗等生命周期规则仍由原执行器负责

| 技能 | 无辅助消耗 | 仅散束 | 仅凝束 | 两者同时 |
| --- | ---: | ---: | ---: | ---: |
| 龙卷射击 | 18 | 23.40 | 21.60 | 28.08 |
| 奥术飞弹 | 7 | 9.10 | 8.40 | 10.92 |
| 冰霜脉冲 | 16 | 20.80 | 19.20 | 24.96 |

这些是本版固定基准的说明值；运行时消耗与预览都读取编译结果，不能再抄写这张表计算。

## 能力资格与伤害作用域分开

`GameData.SKILLS[skill_id].capabilities` 描述技能能接受什么操作，不是伤害标签：

- 龙卷：`initial_projectiles`、`projectile_hit`、`split_projectiles`
- 飞弹、冰霜：`initial_projectiles`、`projectile_hit`
- 其余技能显式声明范围命中、移动、护盾回复或连锁命中等能力；它们没有当前辅助所需的投射物能力

`SupportCatalog.compatibility_reason` 在装配/读取配置时检查这些能力。散束要求初始投射物与投射物命中；凝束要求投射物命中。技能名、快捷栏位置、图标和某次伤害包的标签都不能代替资格检查。

编译出的辅助修饰器固定为：

- `mode = "more"`
- `all_tags = ["hit", "projectile"]`
- `skills = [当前技能 ID]`
- `damage_types = []`，对满足条件的所有伤害分量逐个作用

因此同一技能产生的独立 `hit + area + secondary + explosion` 事件不会继承辅助倍率。普通攻击的 `basic` ID、其他技能的投射物、非命中事件同样不匹配。

回归样例沿用既有 100 物理 + 100 火焰伤害包：全局提高 20%、投射物提高 50%、元素提高 30% 时，投射物合计为 `170 + 200 = 370`；散束为 `296`；再加凝束恢复 `370`。独立范围爆炸的同分量样例一直为 `120 + 150 = 270`。实际龙卷爆炸另外使用其自身火焰系数，不能拿已结算箭伤再次乘算。

## 初始数量、子箭与配方权威

龙卷：

`初始母箭数 = clamp(快照配方.parent_count + 快照.projectile_count + 辅助初始数量加值, 1, 9)`

- `CombatData.TORNADO` 继续是龙卷配方唯一权威；`GameData` 不复制其母/子箭数、速度或系数
- 默认 3 母箭；棱光长弓 +2，散束再 +2，得到 **7 母箭，每枚 3 子箭，共 21 子箭**
- 散束只改初始数量，不把每枚母箭的子箭数也加 2；不会成为 35 子箭
- 保留传入快照中的自定义 `tornado_recipe` 和独立 `explosion_recipe`，不回退覆盖为当前目录默认值

飞弹、冰霜的发射参数统一放到 `GameData.SKILLS[id].projectile_recipe`：

| 字段 | 飞弹 | 冰霜 |
| --- | ---: | ---: |
| `initial_count` | 3 | 5 |
| `spread`，相邻角间距/弧度 | 0.16 | 0.14 |
| `coefficient` | 1.60 | 0.85 |
| `pierce` | 1 | 2 |
| `slow`，秒 | 0 | 3 |
| `speed` | 780 | 520 |
| `damage_type` | lightning | cold |

初始数量只叠加辅助，不叠加棱光长弓的龙卷母箭加值，仍限制 1—9 枚。每枚角度为 `(index - (count - 1) / 2) × spread`，新弹幕仍关于瞄准方向对称；无辅助时与 v0.5 的角度完全一致。

旧 `SKILLS.damage` 从未驱动真实施放，已移除，避免产生第二份表面权威。本次只提取上述三种投射物技能；其余五种技能的既有行为仍由协调器执行，不声称完成所有技能的通用脚本化。

## 编译 API 与失败边界

`SkillCompiler.compile_skill(skill_id: String, snapshot: Dictionary, support_ids: Array) -> Dictionary`

输入 `snapshot` 必须是当前 `BuildState` 给出的、尚未应用辅助的基础施放快照。编译器不读取或修改全局构筑状态。含已编译投射物标记 `initial_count`，或含保留命名空间 `support:` 修饰器 ID 的输入会被原子拒绝，防止重复编译叠乘辅助；即使删除数量标记，也不能重新应用已有辅助。其余五种技能的空辅助快照不添加标记，仍保持原值。

成功结果包含：

- `ok = true`、`error = ""`、`skill_id`
- `snapshot`：保留装备、天赋、珠宝修饰器与效果，追加当前技能的辅助修饰器；递归独立副本
- `mana`、`cooldown`：本次施放和预览使用的消耗/冷却
- `initial_count`：完整初始弹幕数量；非投射物技能为 0
- `recipe`：本次发射配方；龙卷取自输入快照，飞弹/冰霜取自目录；非投射物技能为空字典
- `support_ids`：按稳定 ID 排序的独立 `Array[String]`

对于三种投射物技能，`recipe.initial_count` 与 `snapshot.initial_count` 都记录最终数量。龙卷原始 `snapshot.tornado_recipe.parent_count`、`child_count` 及 `snapshot.projectile_count` 保持原含义；执行器应把编译结果的 `initial_count` 作为 `spawn_tornado(..., requested_count)` 传入，不能再另算一次数量。

其余五种技能仅允许空辅助列表，并返回数值不变的独立快照。失败结果严格只有 `ok = false` 和中文 `error`，不暴露部分配方或已修改快照。

失败封闭规则：

- 未知技能/辅助、重复辅助、超过两个、错误数组内容、能力不匹配，一律拒绝
- 已编译投射物快照和含 `support:` 保留修饰器的快照拒绝再编译；失败不返回部分输出，不改变传入快照
- `SupportCatalog.compatibility_reason(skill_id, support_ids: Variant)` 也拒绝非数组容器，适用于不可信 JSON 存档输入；编译接口自身要求 Array
- 全部辅助元数据先校验再执行，操作仅允许 `add_initial_projectiles`、`projectile_hit_more`、`mana_multiplier`
- 操作名、必需字段、重复操作、能力要求、有限数值与范围均校验；未知操作、额外操作字段、非数字、NaN/Infinity 等不被静默忽略
- 快照基本字段、修饰器作用域、效果 ID、龙卷嵌套配方与飞弹/冰霜配方同样校验，防止半份有效数据进入运行时
- 不修改调用者的数组、字典、JSON 结果或目录；同一结果内部的发射配方与伤害快照也分别递归复制，避免互相污染

## 执行与预览接线

两个槽位绑定技能 ID；换快捷栏位置不改变绑定。装配/卸下通过构筑事务验证，存档和 UI 不得另建一套兼容判定。预览调用与真实施放相同的编译器。

真实施放先编译一次，再检查魔力、冷却与完整初始弹幕容量；全部通过才扣费并执行。容量不够不能只射出半份弹幕，也不能消耗魔力或开始冷却。飞行中的投射物和后代保留本次编译快照；更换装备或辅助只影响之后施放。

`tests/skill_compiler_test.gd` 覆盖纯编译契约、八技能空辅助基线、顺序无关、费用、作用域、独立快照、拒绝重复编译、JSON、操作白名单、畸形元数据与实际 7→21 谱系。施放原子性、UI、槽位绑定和存档迁移由相应场景/状态集成测试补充验证。所有测试必须使用隔离的 XDG 设置、缓存和存档目录。

本阶段明确不包括：用户脚本辅助、未知操作兜底、任意技能/触发器生成、额外递归投射物世代、伤害转换、暴击、持续伤害、宝石经济或完整 PoE 机制。
