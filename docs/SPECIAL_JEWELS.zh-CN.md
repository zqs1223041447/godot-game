# 寻枝晶玉：范围内的远程天赋

v0.9第一种特殊珠宝，原创ID `branchfinder`。可浏览条目与实际树图见[离线图鉴](reference/index.html#jewels-branchfinder)。图鉴和游戏预览读取同一规则分析器。

## 获取与取舍

正常击败一个可发奖励的原始首领时，尝试授予一颗寻枝晶玉。普通装备和每20次有效击杀的随机珠宝里程碑保持；两种条件同次满足时可以分别获得。寻枝不进入旧随机珠宝生成池，也不消耗它的随机抽取。

新档和升级旧档均不补发。F7机制/百怪试验、后代、重复尸体事件没有成长奖励。达到64珠宝上限或背包保留空间不足时，领取失败且已有物品/序号完整保留；后续合法首领仍会再次尝试。

寻枝不提供额外生命、伤害或免费天赋。它占用一个原本可装基础属性珠宝的孔，以路线灵活性换取该孔的其他属性收益。

## 本游戏初版规则

| 项目 | 规则 |
|---|---|
| 激活来源 | 已分配且沿真实连线连通起点的珠宝孔 |
| 半径 | 280个原创天赋树坐标单位，边界计入 |
| 可授予对象 | 小点与大点；不含起点或珠宝孔 |
| 花费 | 每个节点仍消耗1天赋点 |
| 向外延伸 | 远程节点不能作为圈外扩路起点 |
| 多个来源 | 覆盖取并集，任一有效来源均可维持资格 |
| 失去资格的变更 | 原子拒绝，说明受影响节点；先洗相关点或建立其他合法来源 |

280是本树初版可调设计值，不是PoE半径换算。当前12个孔中，内圈孔各覆盖10个可授予节点，外圈各11个；地图距离、战斗相机和UI缩放不改变树中的覆盖关系。

远程节点若后来通过完整的已分配连线接通起点，就成为普通连通节点，此时可以正常向外分配。特殊珠宝不会增加虚拟边或递归赋权。

## 一个分析器处理全部操作

1. 仅以真实图边计算已分配节点中与起点连通的集合C
2. 只有位于C中的孔能激活寻枝，将这些珠宝覆盖的小点/大点汇成集合G
3. 每个C之外的已分配节点必须单独属于G；所有已分配孔必须属于C
4. 分配、退款、拔除、移动、替换、两孔交换和整体重置，都先计算操作后的完整候选再提交

因此不会出现“只改点击规则、保存后却判坏档”，也不会由孤立节点激活另一个远程孔、互相供能或无限扩路。两个珠宝同时提供资格时，不把某节点永久归属第一次分配它的珠宝；拔掉其中一个后会重新检查剩余来源。

交换按最终状态判断，避免合法交换被中间的临时缺源误拒绝。拒绝时不移动任何物品、不改变点数、不发`changed`信号；完整依赖列表保存在分析结果中，界面短提示只列少量名称和数量。

## 界面与存档

T面板保留原布局。选中珠宝孔和寻枝时显示覆盖，尚未激活的孔以灰色预览；远程已分配节点用枝形标记。右栏保持短摘要，完整规则在tooltip与离线图鉴。不能安全拔除/替换时按钮显示原因，不自动洗点。

存档升级为v7，但珠宝仍保留原4字段实例形状。新特殊底材/稀有度只能由v7接受；v1–v6依照各自词汇和规则先验证，再迁移。旧装备、词缀掷值、技能辅助、点数、孔位均保留。

覆盖前以原始字节保存对应`.vN-backup.json`，包括CRLF和UTF-8 BOM。已有备份必须逐字节一致，否则停止覆盖；原路径内容若在加载后被修改也拒绝覆盖。已有损坏/未来版本存档继续受写入保护。

## 参考与原创边界

- [Mark_GGG，2015-04-28](https://www.pathofexile.com/forum/view-thread/1254452/page/2)：半径资格不会使范围外节点获得向外分配能力，是本版避免“孤点继续扩路”的设计依据
- [GGG 3.10.0c，2020-03-17](https://www.pathofexile.com/forum/view-thread/2792025)：更换范围珠宝后需要重新处理失去支持的天赋。本项目选择在变更前原子拒绝，与该历史补丁的失效处理并非相同产品规则
- [GGG 3.21.1 Hotfix3，2023-07，PS公告包含PC说明](https://www.pathofexile.com/forum/view-thread/3406659)：其他珠宝仍提供支持时不能误阻止移除，是替代来源检查的重要边界

上述是可核查的历史机制参考，不声称已复刻当前PoE全部特殊珠宝、节点类型、精通限制、圆环/永恒/星团或数值。名称、280半径、首领投放、可覆盖类型和拒绝事务均为本项目原创适配。
