# v0.63 怪物单火燃烧结算优化

本批只减少内部重复工作。`incoming_burn`已验证原始火焰数值和火抗策略，又自己构造一个单火伤害对象；过去随后通用结算再逐项检查这个已知结构。现在仅普通怪物、数值零魔力分摊及零最大火抗增量的分支，验证原资源后直接构造原完整回执。

公共入参错误顺序、通用`settle_resolved`及所有其他选项沿旧代码。没有把非法公开输入宣称为优化。预测死亡边界现也调用同一入口，因而复用更便宜的相同回执；不更改预测公式、事件分片、归属、持续时间或施放快照。没有缓存、合并小数累加、减少怪物、关闭攻击或跳过奖励。

58,593项纯断言通过，其中58,546次完整typed返回字节与独立冻结v62相同。原StringName actor/stage键、负零、字段插入顺序、typed详情、盾损/血损/过杀、分离的嵌套返回以及调用者输入不变异都有检查。首轮抓到新构造误用String键，按原属性赋值修正；随后仅修测试独立键序预期，原失败记录保留。

## 同状态短场景

测试直接实例化生产Main、Model与BurnRuntime，没有方法计时包装。每次进程独立存档，100个目录怪物保留AI和攻击。初始180投射物是控制负载，玩家保护是采样夹具，不声称自然地图录像。序列化观察放在tick计时外，两边相同。

| 场景 | 旧均值/中位/p95/峰 ms | 新均值/中位/p95/峰 ms |
|---|---|---|
| 24tick无燃烧控制 |52.482 /51.453 /63.996 /71.601|51.052 /49.479 /65.708 /71.942|
| 初始一轮弹体后的150tick死亡/传播 |45.278 /12.432 /148.306 /635.268|34.849 /8.709 /118.826 /564.997|

死亡场景平均耗时约下降23%，中位约30%、p95约20%、峰约11%；150个对应tick中148个候选更快。无燃烧未调用新分支，小幅混合波动完整披露，不称该控制加速。不要把不同场景的百分比相加。

所有逐tick观察和最终磁盘存档严格相同，没有投影：无燃烧29,154,664字节，死亡场景109,388,768字节；27个合法根怪奖励和RNG保留。完整样本、hash和可恢复gzip在本目录qa/v063-settlement。初次完整观察发现重开后、设seed之前的三个随机出生环；只修夹具清理丢弃人口的初始残留，最终仍比较全部rings，未删字段放宽验收。

这只是云端脚本CPU的限定场景改善，残峰仍约565ms，无燃烧控制仍约51ms。没有验证Windows硬件60FPS，也没有解决全部高密度卡顿或首次打开行囊耗时。没有重复历史全量/600秒检测或额外画面验收；既有数值图鉴与字体/素材继续保持。
