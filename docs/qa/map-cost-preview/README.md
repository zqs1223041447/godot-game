# 地图准备前的只读费用与结算预览

基线：`50a4ffc18a36d0ea0811b71e6fb4e85f948226c6`。本分支仅改 Main 只读接口和现有地图装置的一段 Label，不改地图编译器、费用、奖励、实际入场、存档或 schema 55。

控件改变后，界面显示“所选配置 · 尚未准备”，列出所选地图/档位/词缀、既有入场费用、全清结算（须完成后领取）和真实背包碎片余额。不足提示随余额变化刷新。数值直接来自 `MapCompiler.compile_normal()` 的 `fee` / `completion_reward`，不新增奖励公式；档位解锁状态读取现有 `NormalMaps.tiers()`。独立测试地图明确免费且无正式地图结算。

无效或未解锁的配置只显示现有权威原因，清除预览费用和结算。原已准备草案、修订和开启门控保持原逻辑：即使控件改回原值，仍然“尚未准备”，不会自动采用旧草案。显式准备后预览隐藏，恢复原权威摘要；实际合法入图才沿原事务扣费。

## 针对性验证

- 新 `map_selection_cost_preview_test.gd`：headless **59 项 / 0 失败**，X11 / Mesa llvmpipe **60 项 / 0 失败**，多一项截图保存。使用有限 canonical 解锁/结算夹具和已有 8/4 碎片宝石购买，得到三碎片余额；这是 UI 夹具，不声称进行战斗或经济平衡验证。
- 控件信号验证 III 档及既有词缀奖励、特殊波次门槛、超量普通/特殊词缀、返回原配置仍阻止开启、明确准备、旧 revision 回调拒绝、关闭/重开、正式/测试入口分离。非法地图、类型和未解锁档位的只读 API 返回具体原因，且没有费用/结算字段。
- 实际背包回收宝石把三碎片变为四碎片，预览清除不足提示而保留选择。预览、无效输入、回到原值和世界刷新逐字节比较完整模型、磁盘、草案、世界、地图运行、保存计数和 RNG；同时记录准备 API 调用次数，确保没有自动准备。
- 最后一次真实合法断垣 II 入图扣除四碎片，生成一个正式 run；旧回调和重复开启不再扣费。预览和显式准备均没有库存写入、扣款或创建 run。
- 原草案摘要检查 **28 项 / 0 失败**，原余额刷新 **53 项 / 0 失败**，原特殊词缀门槛 **200 项 / 0 失败**。这些既有测试源码未改，输出另存本目录；历史摘要结果已恢复。
