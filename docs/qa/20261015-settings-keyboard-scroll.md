# 设置页键盘焦点滚动回归（2026-10-15）

## 缺陷与最小修复

设置页的 `PanelScroll` 原先不跟随焦点。实际 Tab 可移到内容裁切区外的“恢复默认显示”和“返回暂停菜单”，最大字体与最大 UI 比例时还包括“角色装饰动画”。独立实例探针在全部 9 组支持比例中复现 4 组裁切，单独启用该实例的 `follow_focus` 后全部消失。

生产改动只扩大已验证的暂停页赋值：`scroll.follow_focus = panel_name in ["pause", "settings"]`。不改导航顺序、控件尺寸、设置值、玩法或保存逻辑；其他面板仍使用默认关闭跟随焦点。暂停页回归原有真实点击、确认取消与数据保护断言保留，仅调整面板范围断言。

## 回归方法

`tests/settings_keyboard_scroll_test.gd` 使用真实 `main.tscn` 和正式离镇练习 API，停用战斗与 HUD 的逐帧处理，保留 UI 输入。

- 每组仅指定起始焦点与起始滚动位置；随后向 viewport 注入真实 Tab/Shift+Tab 按下与释放，依次经过 UI 缩放、字体、特效、伤害数字、动画、恢复默认和返回七个控件，并倒序返回
- 每一步验证真实焦点归属、排除可见垂直滚动条后的内容裁切区，以及实际逻辑 viewport 内完整控件矩形；舍入误差不超过 1 个逻辑像素
- 末端控件原先在裁切区下方时断言实际向下滚动；返回时首控件若在裁切区上方，断言实际向上滚动。已全部可见时不强求无必要滚动
- 每组只在导航前设置支持的字体/UI 输入，导航期间全部五项显示设置保持原值；不激活恢复默认或修改设置来制造可见性
- 检查 Canonical 全快照、正式与练习保存原始字节、显示设置文件字节、运行修订、当前遭遇选择、场景 RNG 与全局 RNG 都保持不变；正式保存须实际存在
- 断言跟随焦点仅在暂停与设置窗口开启
- 外部 90 秒超时、脚本内部 75 秒保护；要求 Linux 新 `/tmp/godot-*` 隔离 XDG，避免触碰用户数据

## 覆盖及边界

请求窗口 1280×720 和 2560×1440，分别遍历 `VisualSettings.FONT_SCALES`（1.0/1.1/1.2）与 `UI_SCALES`（0.9/1.0/1.1），合计 18 组。每组读取、报告并断言真实逻辑 viewport 为 1280×720。项目使用 `canvas_items` 拉伸，两种窗口请求不是两种不同逻辑分辨率。

此测试证明焦点到达和逻辑裁切区可见性，不宣称设置选项功能全覆盖、Windows 原生画面、截图、FPS、性能或全量回归通过。

## 可复现命令

```sh
xdg=$(mktemp -d /tmp/godot-settings-keyboard-XXXX)
XDG_DATA_HOME="$xdg/data" XDG_CONFIG_HOME="$xdg/config" XDG_CACHE_HOME="$xdg/cache" \
  timeout 90 godot --headless --path . --script tests/settings_keyboard_scroll_test.gd
```

负向对照使用另一个全新 XDG 目录，命令末尾添加 `-- --disable-follow-focus`。只在测试实例上关闭跟随焦点；正常可见性、真实输入与数据保护断言不放宽；每组完成后恢复原跟随焦点值，避免测试自身的禁用状态污染下一组生产配置断言。预期非零退出，不调用辅助滚动，也不改布局或扩大允许误差。

## 本地结果

Godot 4.6.3 Linux headless：正常运行 1025 项、0 失败，退出 0；禁用跟随焦点的负向对照 1025 项、36 失败，退出 1。正常末端滚动在有裁切的比例组为 11/43/13/79，最大比例逆向回到 60，所有目标完整可见；无需滚动的比例组保持 0。负向末端均为 0，暴露内容裁切和缺失滚动，全部设置、存档及 RNG 保护检查仍通过。
