# 确认的代价与保留边界

只读确认当前全局推进包含正事件时刻与全部活跃燃烧状态的乘积。v095 已保存的第0帧有343次全局推进调用、9263次预测 incoming_burn、9263次真实燃烧结算，342次命中、最终100燃烧状态、0击杀。不能把18526解释为342×100，也不能把该峰归因于死亡队列；状态是在帧内逐渐形成的，相同时间刻已有快路。

Main 的预测局部变量只消费 ok/damage_total；固定参数 shield=0、health=1 是为取得每秒防御后总量，其虚拟盾血扣除及完整回执未进入 trace、反馈、状态或外部观察。v096 因而只移除这个不用的结算构造，保留 profile 和同一权威标量公式。实际命中前的全体推进、分段资源写回、死亡与传播仍原顺序。

不能在本候选中删正时间片：原来的 raw_dps×width、减伤、盾血相减、total_damage 和反馈加法逐段执行，合成宽区间可能改变舍入及跨盾的分量。原死亡预测每次使用先前扣除后的资源，持久缓存死亡时刻可能改变ULP边界。burn_trace 原样保留。

若本候选达不到保留标准，就终止这一预测回执方向，不连续试微变体。它不降低事件×状态复杂度，也不是卡顿根治。进一步算法改变必须独立明确哪些内部观察可以重新定义，并证明同刻死亡/刷新/传播/到期/奖励语义；本批没有授权或实现这类时间轴变更。
