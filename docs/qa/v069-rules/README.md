## 关键反例

1. 局部武器先结算 `(4+2)×1.2`，再乘技能系数2；固有120、外加5和武器14.4合为物理139.4。转换记录为剩余83.64、转火55.76；原生火90和原始 `base` / `assembly` 的类型化字节完整保留
2. 转换片的提高按物理、火焰、元素及原命中标签匹配后相加；一条同时匹配物理与火焰的修饰只计一次，原生火不继承物理提高。法术标签或其他技能限定不因转换而得到匹配
3. 两条共享 `focus` 标识的独立MORE句分别提供1.2及0.8，转换片必须得到0.96；收据同时保留两个标识和原数组下标 `[0,1]`。额外一条同时匹配物理/火焰的MORE仍只应用一次
4. 原物理100、原生火50，40%转换，暴击×2，火抗50%，护甲600：防御前物理120、火180；最终物理60、火90。共享结算只收到两个最终类型记录，护盾先花20，生命损失130、剩余70。火焰原生/转换片的防御前值分别为100/80
5. 缺失开关、整数/浮点零、负零、无物理、显式零物理及纯火独立爆炸不增加转换字段；有效零路径返回深副本且完整字节一致
6. 不接受额外字段、缺字段、非40%比例、近似但不精确的派生值、只守恒的伪造30%拆分、篡改源基础/组装记录、重复转换、DOT、非数值/非有限值及有限数相加或相乘后溢出；解析失败不返回部分伤害收据
7. 输入、输出、重复结果和共享防御收据各自拥有嵌套数据；转换解析不消耗全局随机数

## 接口边界

`physical_fire_conversion_rules.gd` 提供 `snapshot_error`、`from_stats`、`apply` 和 `profile`。公开 `apply` 必须收到完整有效的已组装包；关闭或没有物理时返回完全相同内容的深副本。启用时只附加六字段 `conversion`，不重写原始点数。

`DamageResolver.conversion_error` 是拆分记录的唯一算术验证权威；基础包验证器先维持原有结构、组装和事件检查顺序，最后检查可选转换。新解析分支每个最终类型只返回一个 `{type,before_defense,resistance,final,parts}` 收据，各片包含类型来源、基础、提高、MORE、实际暴击后/防御前值、修饰标识和原修饰数组下标；不构造失真的聚合提高/MORE。

本测试不代替源天赋分配、存档迁移、施放冻结、投射物或实际场景验收；这些由同批对应集成验证覆盖。没有支持多段转换、额外获得伤害、转换持续伤害或改变原命中标签。
