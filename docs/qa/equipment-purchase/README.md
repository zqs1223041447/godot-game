# 正式城镇基础底材购买

基线：`cf90d198b7b376b801e8363ca4f1a9105f5f1eb8`。这是供父任务审查的独立功能分支，尚未合 main；不包含任何模型 WIP。

正式城镇原先只有宝石商人可付费交易，装备商人仅在独立测试档免费供应。现在正式玩家可用地图结算的校准碎片，定向购买现有目录中的普通无词缀底材，再通过现有赋魔/装备流程构筑。每件 **8 校准碎片、物品等级 1**；更高物品等级仍由地图掉落取得。目录、掉落权重、装备属性、INC/MORE 汇总、制作费用与结果规则均未改动。

入口沿用城镇场景的装备商人、服务面板及购买确认窗。只供应 `EquipmentCatalog.all_base_ids()` 中的真实底材；正式供应不含固定机制装备、药剂、珠宝或免费货币。原测试商人的全部免费供应，包括等级 30 底材，保持原行为。

`scripts/items/equipment_purchase.gd` 是有界的底材购买服务：在现有库存快照上先扣除实际背包碎片，再用现有分页格子算法放入底材，最终调用现有 `_commit` 一次校验/原子写盘。购买不调用 RNG，也不自动装备或重排背包。扣款可释放货币格子，但只有真实装备尺寸确实放得下才报价成功。

最多保留八个一次性报价。确认绑定模型身份、区域修订、库存快照、原存档字节及确切底材 ID；返回给界面的价格和等级不充当权威输入。取消、切换服务、关闭窗口、库存变更、区域切换、测试档切换使原报价不能兑现。写盘失败保留物品、碎片及序号，必须重新报价后重试。复用现有正常档守卫、磁盘收据、货币堆与入包机制；没有建立新钱包。

仍使用 **schema 55**，没有迁移、新持久字段、新底材或新效果枚举。撤回功能代码后，已买物品仍是旧基线可加载、装备和制作的普通目录物品。撤回代码不会自动退回已经成功支付的购买费用。

## 有界验证

- 事务测试：`equipment_purchase_transactions_test.gd`，115 项 / 0 失败。逐个目录底材购买并确认真实赋魔资格；包括参数类型、余额不足、碎片扣除后碎片格子不足以容纳大装备、可用矩形空间、序号终点、跨模型、跨区域、旧报价、取消、重复确认、九个报价淘汰最旧项、外部存档改字节、写盘失败与重试、changed 信号重入及精确重载。
- 主场景 headless 流程：72 项 / 0 失败。四次真实、有限的旧庭 I 地图完成，合计 100 个合法根怪/首领击杀；原奖励提供 16 枚碎片，用于购买锻纹短刃与现有赋魔，各 8 枚。后代不增加根怪奖励。经过真实商人按钮和确认信号，将魔法短刃放入武器槽，现有基础攻击编译器切换为近战。购买保留游戏 RNG、暴击流、药剂与技能冷却。随后区域/测试档边界测试的 8 枚碎片是显式夹具，未用于证明上述购买/赋魔的资金来源。
- 原生 X11 / Mesa llvmpipe：70 项 / 0 失败，完成上述核心流程并捕获一次 [购买确认](merchant-confirmation.png)。随后新增的跨商人共享确认测试只在最终 headless 流程验证；没有重复原生画面验收。原生报告保存准确的历史检查数量，不冒称新增项已原生跑过。
- 附带旧宝石事务检查：本分支和未改运行源码的基线均为 330 项 / 2 失败；失败是第 148、195 行仍写死当前宝石目录为 26 项。相关宝石模型、目录、存档和旧测试源文件相对 main 完全一致。两个原始日志一并保留；没有将此报告成通过或借机修改旧测试。

全新 Linux XDG 目录隔离了所有写入。资源已由 Godot 导入后，可运行：

```sh
bash tools/validate_equipment_purchase.sh
```

这个入口只运行新增事务及主场景测试，每个进程限时 45 秒，不启动历史全量或 600 秒检测。`headless-report.json`、`native-report.json`、日志及源 SHA 记录实际证据。

尚未验证 Windows 成品、真实硬件性能或长期经济平衡。没有导出 Windows、封包、下载/转换模型或升级存档。旧模型研究/WIP 仍留在其他分支。
