## 商品、价格与掉落定位

现有 `JewelData.BASES` 有三种基础珠宝，但合法实例只支持魔法和稀有品质、且必须有词缀，不支持普通无词缀实例。因此正式商店沿用 `TownCatalog.make_item()` 已有的固定最低数值魔法样品，不建立新词缀、生成器或珠宝规则：

| 现有底材 | 固定现有词缀 | 价格 |
| --- | --- | --- |
| 烬心晶玉 `emberheart` | 伤害 +2、攻击速度 +0.04 / 秒 | 8 校准碎片 |
| 雾潮晶玉 `tideglass` | 伤害 +2、魔力回复 +0.3 / 秒 | 8 校准碎片 |
| 岚纹晶玉 `windweave` | 伤害 +2、攻击速度 +0.04 / 秒 | 8 校准碎片 |

价格直接读取既有 `JewelCraftRules.REFORGE_COSTS.magic`，参照现有魔法珠宝整体重铸成本，无新定价表。两个无词缀正式 I 档地图的基础结算各 4 碎片，可以购买一件。既有魔法珠宝回收仍只返 1 碎片，不能购买后套利；整体重铸继续沿用原流程。

自然掉落仍沿 Main 每 20 次合法奖励击杀的原珠宝生成路径，具有原来的魔法/稀有品质、词缀池、数量和数值范围。商店提供可定向选择的最低数值样品；不改变地图掉落或购买时随机。`branchfinder` 寻枝晶玉及其他特殊规则不在正式商品中，原特殊珠宝掉落和独立测试供应不变。

## 最小接入

`JewelPurchase` 继承已有装备购买服务，只提供三项实例、价格和报价展示适配，并提供珠宝商品列表。装备购买服务的原实例工厂、价格和展示保持原结果；两种购买复用同一报价/候选/收据/一次保存实现，避免复制交易逻辑。各商人仍拥有独立的有界报价集合。

正式城镇沿原珠宝商人、三行商品和共享确认窗购买。确认列出确切现有词缀和最低数值；采用既有珠宝图标控件，无新美术素材。确认后只将真实 UID 的一格珠宝放入背包，不自动镶嵌，不赠天赋点，不改变连通或分配规则。

扣除背包物理碎片、放入真实尺寸物品及完整构筑校验通过后，仅调用原 `_commit` 一次保存。旧报价、目标变化、外部改档、取消、区域/模型变化、写盘失败、满包和余额不足均保留原物品与碎片。测试免费领取接口仍拒绝正式存档；特殊测试商品从未纳入正式列表。

数据仍为 **schema 55**，没有新持久字段、货币、底材 ID、词缀 ID 或特殊效果。购买后的实例可由原基线合法加载和使用。
