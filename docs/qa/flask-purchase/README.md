# 正式城镇基础药剂购买

基线：`e6f10f2c414dedcc56be11526dd4d0b95b644e5c`。独立恢复分支：`codex/normal-flask-purchase-recovery`，提交供父任务审查，未合 main。原药剂任务的环境与未提交 WIP 未访问、覆盖或删除；若其成果随后返回，由父任务对照择一保留。

正式装备商人保留全部 **15 个现有底材**，追加现有 `flask:life` 和 `flask:mana`，每瓶 **8 校准碎片**。价格沿现有基础装备同档，由父任务明确授权；目录中的使用消耗 10 是充能成本。药剂不支持装备/珠宝回收或宝石回收，既有丢弃不返碎片，不能通过购买和回收套利。

`FlaskPurchase` 继承现有 `equipment_purchase.gd`，仅适配现有实例工厂、商品列表和报价展示；报价、候选库存、磁盘收据与一次 `_commit` 保存复用原代码。正式商品合并及共享确认窗接入沿原商人路由。购买只扣背包真实碎片并将一个新 UID 放入 1×2 背包空间，不自动装备，也不调用赠送或奖励接口。

现有 schema 55、药剂目录/实例 payload、使用效果、地图补给和充能、赠送迁移与奖励计数、库存与保存权威、装备/珠宝购买核心代码均未改动。新 UID 通过既有 `sync_owned()` 初始化 30 充能；旧 UID 的充能和已开始的恢复保持。购买后通过原行囊激活、五槽药剂栏及 HUD 使用。

## 有限验证

Godot **4.6.3**，全新 Linux XDG 目录，每个测试进程限时 **45 秒**：

- 药剂事务：**58 项 / 0 失败**。两件现有实例与空 payload、八碎片一次扣款/入包/保存、精确 schema55 重载、非法目标、类型与 UID 边界、取消/重复确认/目标或上下文变更、跨服务/模型、旧库存和外部存档字节、写失败与新报价重试、展示价格篡改、正式/测试路径、余额不足、回收拒绝及丢弃不退款。
- 真实 1×2 空间：满包中仅释放一个碎片格或两个横向格均拒绝；碎片余额 16 时扣 8 后剩余堆仍占格拒绝；余额 8 时堆完全释放并与下方空格组成真实纵向 1×2，扣款和入包同时成功。
- 药剂主场景 headless：**79 项 / 0 失败**。四次真实、有限的旧庭 I 地图完成，原奖励赚取 16 碎片购买两瓶，资金未注入。经过真实商人按钮及确认信号，重复回调只保存一次，取消/旧库存/跨商人及离城返城报价失效；原行囊激活装备两瓶，原 HUD 使用，原基础 35%/3 秒恢复和 10 充能消耗，正式/免费测试档隔离，重载及奖励计数保持。
- 旧运行状态的防御性夹具：使用原 `FlaskRuntime.use/advance` 为已有生命/魔力瓶建立 20 充能和进行中的恢复；城镇实际使用仍被原安全区规则阻止。两次购买与装备均保留旧瓶状态，只有新 UID 初始化。该夹具不是购买资金或正常城镇使用流程。
- 原生 X11 / Mesa llvmpipe：**80 项 / 0 失败**，比 headless 多一项截图检查。[购买确认截图](confirmation.png)已实际查看，名称、35%效果、10充能、8碎片价格及确认/取消均可读。无物理鼠标自动化。V-Sync 限制及无音频设备转 Dummy 的环境日志保留；不是真实硬件性能或音频验收。
- 受影响回归：原装备事务 **115/0**、装备主场景 **73/0**；原珠宝事务 **48/0**、主场景 **43/0**。装备主场景仅调整商品范围断言为 15 底材 + 2 药剂，保留原全部装备行为断言。原装备报告已恢复，新报告另存本目录；未改旧珠宝测试。
