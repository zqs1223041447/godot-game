# 诊断单批候选：停止，未接生产

本候选在工具目录子类中运行。全部scripts/assets/scenes/data/project.godot与d2d188a原字节相同；没有生产开关，也不会合入生产算法。

## 结果

事前保守准入能把明显致死、带盾、到期相等及未知门禁批次整体交回原Main。真实Main小夹具中，4个回退组完整观测逐字相同；获准组只有trace分段变化。纯guard的临界、编译快照与暴击校验记录在../v097-batch-guard，原错误/修正分组均保留。

但一次20帧密集样本仍产生真实玩法差异，候选终止。完整比较有140项严格差异：1个hit health_lost、4个visible反馈key顺序、62个sequence、62个id和11个补给位置。最后11项是3个位置在多帧持续的差异，例如frame16由(1055.9880,304.8293)变为(918.4934,345.1349)。Main每第4个奖励击杀在死者位置生成补给，因此这是死亡/奖励落点相关差异，不能用浮点或显示容差放过。

观测中的敌人身份/次序、击杀数量、奖励数量、RNG、角色物品与嵌入存档字节相同，不等于完整死亡回调次序和归属已证明相同。当前记录不直接认证全部精确死亡时刻。可见反馈集合键相同，但顺序与ID改变；期限字段没有差异。没有为挽救候选改显示规则。

6,045个获准数值误差均未超界：生命1,548、同一生命的目标索引副本1,559、pending amount/health_lost各1,254、visible amount/health_lost各205、total_damage20。最大绝对误差1.2505552149377763e-10，最大相对误差1来自0与-3.3306690738754696e-16两个非正尸体值。两生命路径均要求正/非正类别一致。全部6,185条非零差异保存为JSONL压缩件，未用通配过滤。

首次比较遗漏了观察器内同一敌人health的索引镜像，将其归为严格字段；修正仅该精确路径并加入存活正负类别门禁。最初比较器/JSON/日志保留。之后所有分析都读取原20帧文件，没有重跑游戏或再次放宽容差。

## 停止理由与后续边界

“当前批一定不死”不能保证改变扣血舍入后未来帧仍按同样次序死亡。合并区间产生的微小差值带入后续阈值，已改变补给位置。要保持未来离散结果，需保留原cut的标量累计次序，或另行明确新的数值规则；本批未实现或授权改变数值规则。

本轮结束，不继续修比较器/feedback或实战候选。不重跑压力样本、不自动打包。影子队列/依赖工具和失败证据仅作为后续设计参考；不是已上线优化。
