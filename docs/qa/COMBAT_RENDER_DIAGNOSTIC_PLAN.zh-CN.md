# 怪物密度与持续战斗诊断

基线为已发布 v0.22 的 `4ae0f1020c23fd235e45304a71cc0728b8dc960d`。本分支只放隔离诊断工具与可关闭的绘制分段计时，不作为游戏功能修复或下一版本发行。

## 负载与隔离

- 每个场景单独进程、单独XDG存档目录，运行100/200/400只真实目录怪物
- 发布游戏上限仍为100；200/400只通过测试夹具调用同一个MonsterRuntime目录工厂创建，明确属于越上限压力负载
- 保留目录生命、攻击、速度、碰撞半径、现有180投射物/180粒子上限及原死亡奖励处理。角色无敌用于让采样持续，不能据此代表真实玩家受击反馈成本
- crowd仅观察AI群聚与绘制；combat使用现有龙卷示例、正常普攻与真实技能耗魔/冷却，保持原XP、物品奖励、自动保存和谱系清理
- 每10秒注入一次20%目标的受控致死伤害，调用原死亡/奖励链；与正常投射物击杀分别标记，不当作正常DPS或自然击杀率
- 持续120秒仿真每10秒分桶，随后停止攻击与补怪并自然推进30秒，使22秒生命补给和短效表现自然清理
- 仿真固定60tick/s。原生绘制另测实际提交CPU、墙钟帧间隔和绘制调用数，llvmpipe结果不代表Windows硬件FPS

## 记录与解释

记录AI分离候选访问数、飞弹/特效/拾取/生成清理、同步进度与保存、HUD刷新CPU。build_changed_nested和save_nested是包含在外层流程里的嵌套计时，不相加冒充总耗时。

绘制分段使用原函数与相同顺序：环境、拾取、环形提示、前层提示、预警、深度排序、名字选择、角色、投射物、玩家、血条与名字、后层提示、粒子、伤害文字。诊断开关默认关闭，计时仅记录时钟差，不使用RNG或改变游戏输入。

观察节点、孤立节点、资源、对象、静态内存及所有表现/奖励容器，比较短时与持续采样，判断是否随运行累积。存活目标保持固定密度，死亡目标下一tick由原清理路径处理；每批新根身份持续递增。

截至本阶段只完成100怪短场景的工具启动验证，未将任何候选代码路径宣布为已确认瓶颈。下一步以全部分桶结果定位，再提出保持结算/画面语义的最小修改，不预先降低怪物数量或画质。
