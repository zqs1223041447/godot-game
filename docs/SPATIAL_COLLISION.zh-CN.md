# v0.8 空间候选索引

## 不改命中的优化边界

`SpatialTargetIndex` 只缩小候选集。每只敌人以原始世界坐标、原始 `radius` 的圆形外接框覆盖网格；不会按生命、出生保护或屏幕可见性移除目标。最终投射物碰撞仍调用原有 `_segment_circle`，传入**投射物原始半径 + 敌人原始半径**，没有缩小碰撞盒、近似最终命中、改变伤害或改变生命周期。

返回值是目标数组的**原始下标，升序排列**，不是敌人 ID。不同下标即使指向同一 Dictionary，也保留两次原始遍历语义。窄阶段仍按 `t` 再按目标 ID 排序；出生保护、死亡过滤、分阶段命中账本、穿透消耗、全局时序、分裂容量仲裁、返回和自然结束事件均沿用原逻辑。

## API 和更新契约

- `rebuild(targets: Array[Dictionary])`：引用当前目标数组，重建一次
- `update(index: int)`：位置或半径变化后更新该下标；同时更新指向同一 Dictionary 的所有别名下标
- `query_aabb(rect: Rect2)`：返回覆盖矩形的保守候选
- `query_circle(center, radius)`：查询圆的外接框；不会把外接框当最终圆形碰撞
- `query_sweep(start, end, expansion_radius)`：查询扫掠线段的外接框并扩张给定半径

敌人移动必须保留顺序：先查询 `enemy.radius + 3.0`，用原来的精确距离判定和原始顺序累加排斥，再写入最终限界后位置，立即 `update(index)`。这样后面的敌人仍能看到前面敌人在本帧的新位置。其他敌人的半径已在索引覆盖范围内，不应遗漏，也不需再次用最大半径扩张。

数组换序、同长度替换元素或替换字典身份后必须 `rebuild`。数组长度变化会在有效查询/更新时自动重建，但常规调用者仍应按帧明确重建；索引不监听任意外部字典写入。

## 数值和工作量上界

默认网格边长为 128 世界单位；构造器允许其他正有限值。负坐标使用向下取整。零尺寸框、零半径、恰好落在格边界的圆仍会被覆盖。

每次插入或查询最多遍历 4,096 格，单轴格坐标绝对值不超过 1,048,576。超出安全范围、非有限或无效查询退回全部下标；无法安全索引的目标放入每次查询都包含的保守候选集合。这个上限只改变性能路径，不丢弃目标。

格界使用至少 0.01 世界单位或坐标量级的百万分之一作为舍入余量。扫掠框另加至少 0.01 世界单位或线段长度的千分之一，覆盖引擎 Vector2 单精度运算在长距离近切线二次判别式中的误差。所有余量**只用于候选阶段**；精确 `_segment_circle` 完全未改。

## 投射物运行时和可复现计数

`ProjectileRuntime.advance` 每次有效调用只重建一次索引，后续各个分段、子箭和返回段共用它。`use_spatial_index = false` 保留全量扫描参考模式，仅用于开发验证；没有新增玩家设置。直接在 `advance` 以外调用 `_contacts` 时始终扫描传入的当前数组，避免使用旧索引。

每次 `advance` 重置以下计数，包括无效/零时间步：

- `last_candidate_visits`：实际进入原始目标过滤/窄阶段循环的下标次数
- `last_full_scan_visits`：同样分段调度下全扫描应访问的目标次数
- `last_contact_queries`：本次 `_contacts` 次数
- `last_indexed_queries`：通过索引 API 发起的次数，包含安全退回全扫描的查询

这些计数包括之后会被生命、出生保护或命中账本过滤的候选；不是实际命中数，也不是帧率。每帧总耗时还包括索引重建、格遍历、排序、实际事件/伤害和渲染。

## 回归和测量

运行 `tests/spatial_collision_test.gd`，使用和 `tools/validate.sh` 一样的隔离 XDG 数据、设置与缓存目录。测试涵盖：

- 完整事件字典、伤害包/快照、幸存及已终止母弹状态的逐值参考比较
- 100 个 `MonsterCatalog.make_enemy` 真实游戏字典、180 枚真实投射物
- 零半径、精确切线、格边界、负坐标、高速扫掠、极大/无效界限
- 相同引用、重复 ID、数组换序、可变位置/半径和别名更新
- 出生保护、死亡、既有命中账本、子箭、返回、到期、容量拒绝与跨帧分段
- 固定随机种子 `808100180` 的 80 组随机差分
- 分布及聚集敌人在 40 帧顺序移动后的完整字典相等

固定分布夹具在约 1,840 × 710.769 世界区域内放置 20 × 5 敌人网格。180 枚半径 6 投射物各从目标左方 35 世界单位出发，以 420 世界单位/秒运行 0.12 秒：**491 / 18,000 次候选访问，减少 97.27%，仍然精确产生 180 次命中**。顺序排斥含两个跳过移动的敌人及一个引用别名：**204 / 9,800 次候选访问，减少 97.92%**。

全体 100 只敌人完全重叠时，保留 **18,000 / 18,000 次候选访问和命中**；不通过漏判制造性能收益。测试只把确定性候选减少作为分布场景门槛，打印的机器耗时不作为测试成败条件，也不声称等比例帧率提升。


## 调度队列的保守排序复用

百怪/180弹计时另外暴露旧调度器在每次取出工作后重排全队列的开销。`use_cached_work_order`默认开启；关闭它可逐步重现旧每次取出前排序。

只在以下条件全部成立时复用已经排序的工作队列：时间全部有限；投射物ID互不重复；单独按数值排序的时间数组中，不存在「数值不同但任一方向`is_equal_approx`成立」的相邻时间。这避开近似相等不具传递性带来的历史排序歧义。完全相等的时间继续按原优先级和唯一ID决定顺序。

仅弹出首项不改变其余工作的时间、优先级或ID，因此严格次序保持；加入子箭或后续返回段会立即使缓存失效并重新排序/证明。含近似歧义或重复ID的批次继续沿用原逐次排序，不采用新的堆顺序或时间量化。

`last_work_sorts`、`last_work_sort_skips`、`last_work_order_checks`记录实际排序、复用次数和证明次数，每次`advance`重置。`tests/projectile_schedule_test.gd`以历史开关关闭模式逐值核对事件、投射物与序列，并检查模糊时间、重复ID、生命周期、容量和满弹场景；`tests/density_benchmark.gd`联合比较历史扫描/排序与两项优化后的完整场景。
