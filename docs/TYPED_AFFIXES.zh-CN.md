# v0.7 类型化附加伤害：有界原创词缀契约

本版把「攻击 / 法术命中附加某类型伤害」接入真实随机装备、装备属性、施放快照和伤害来源记录。它是本项目的**原创定点语义适配**，不是完整 PoE 伤害引擎；研究导出表不进入运行时。

## 1. 新内容与旧目录隔离

旧公开 `EquipmentCatalog.BASES` 仍只有原来的 6 个底材，`AFFIXES` 仍只有原来的 12 类词缀。底材属性、描述、名称、格子尺寸、词缀组、词缀档位和权重全部保留；旧 `generate()` 的随机调用顺序和结果不变。

新内容独立放在 `EXPANSION_BASES` / `EXPANSION_AFFIXES`：

- 底材 `runewood_focus`：**符木法器**，武器槽，占 **1 × 3** 格
- 固有属性：最大魔力 **+8**、魔力恢复 **+0.25 / 秒**
- 不含固有 `damage`，不改写旧底材的角色通用基础伤害，也没有局部武器物理伤害阶段

| 新前缀 ID / 运行时属性 | 原创名 | 必须匹配的命中标签 | 附加伤害类型 |
|---|---|---|---|
| `attack_added_physical` | 砾刻 | `hit` + `attack` | `physical`，物理 |
| `attack_added_fire` | 焰刻 | `hit` + `attack` | `fire`，火焰 |
| `spell_added_cold` | 霜铭 | `hit` + `spell` | `cold`，冰霜 |
| `spell_added_lightning` | 雷铭 | `hit` + `spell` | `lightning`，闪电 |

四类均为 `prefix`、`unit=flat`，各自使用独立互斥组。每类都声明：

- `stage=skill_added_damage`
- `scope=equipped_character`
- `required_tags` 为表中的两个标签
- 明确的 `damage_type`
- `allowed_base_ids=["runewood_focus"]`，只允许符木法器

旧 6 个底材即使是武器，也不能生成或读取这四类新前缀。符木法器可以同时使用兼容的旧武器词缀：深汲、符歌、折辉、远织四类前缀，以及藏炭、霜回、引霆、泉旋、连拍五类后缀。合计 8 类前缀、5 类后缀，足够填满 3 前缀 + 3 后缀的稀有物品。

## 2. 原创档位与固定掷值

| 本项目档位 | 最低物品等级 | 选择权重 | 生成时可掷整数 |
|---|---:|---:|---:|
| T1 | 1 | 100 | 1–2 |
| T2 | 8 | 60 | 3–4 |
| T3 | 16 | 30 | 5–6 |

物品等级仍限制为 1–30。这里的 T3 是本项目的较高档位，不是照抄其他游戏的编号。

**范围只用于生成物品时选出一个整数，保存的是这个唯一数值。** 例如 T2 掷出 4，装备后提供固定 4 点对应类型附加伤害；每次命中不再掷随机数。实例没有「最小伤害 / 最大伤害」端点，也没有命中时 RNG。

词缀选择以每个已解锁的「家族、档位」为独立加权候选；选中家族后移除同组所有档位，不能靠不同档位重复占用同组。普通 0 词缀；魔法 1–2 条、最多 1 前缀和 1 后缀；稀有 4–6 条、最多 3 前缀和 3 后缀，不允许静默少发词缀。

## 3. 自然获取概率

以下75/25描述保留v0.7历史接口。v0.11自然战斗改用当前60/25/15三池分配，且灰烬守卫指定防御池；见[FIRE_DEFENSES](FIRE_DEFENSES.zh-CN.md)。`generate_loot()`本身和本节历史样本保持不变。

自然奖励使用 `generate_loot()`：在请求校验成功后，先选择 **75% 旧目录 / 25% 扩展目录**，然后只生成**一件**物品。

- 旧目录内 6 个底材等概率；每个旧底材占自然装备生成的 12.5%
- 扩展目录目前只有符木法器，占自然装备生成的 25%
- 未指定稀有度时仍是普通 30%、魔法 55%、稀有 15%
- 指定稀有度时保持指定结果；稀有怪 / 首领的稀有奖励不会被重新掷成普通
- 25% 是底材概率，**不是保证获得新附加伤害词缀的概率**。普通符木法器没有显式词缀；魔法 / 稀有符木法器仍会与兼容的旧前缀竞争

既有奖励节奏不额外加发物品：普通原始怪的有效击杀计数每 8 次尝试发一件；稀有与首领原始怪尝试发一件稀有装备；同一次死亡最多一件。后代、重复死亡通知和 F7 试验场不提供该奖励；背包或藏品容量不足时拒绝，不覆盖已有物品。创建角色、加载或迁移存档不赠送符木法器，也不把测试样本注入真实构筑。

三个生成入口的签名一致：`(rng, id, item_level, rarity="")`。

- `generate()`：冻结的旧目录
- `generate_expanded()`：明确选择扩展底材，用于受控调用和自动测试
- `generate_loot()`：自然奖励混合池

无效 ID、越界等级、未知稀有度或缺失 RNG 均先拒绝；不消耗池选择、稀有度或词缀的任何随机数。

## 4. 属性、事件与来源

`base_definition(id)` / `affix_definition(id)` 可读取两套目录，返回包含嵌套字典和数组的深拷贝；外部修改返回值不影响定义。原有 `get_stats(instance)` / `definition(instance)` 也支持两套目录。

新前缀提供的是装备角色的对应属性点数。事件仅选择与自己 `hit` + `attack` 或 `hit` + `spell` 标签匹配的类型加值，再按该事件明确的 `added_effectiveness` 组装基础伤害。提高、更多和目标抗性继续由原有解析阶段处理。武器槽不意味着局部武器词缀；附加伤害也不改写角色的旧 `damage` 标量。

符木法器上攻击词缀与法术词缀可以共存，但一次命中只使用自己的作用域。独立爆炸维持独立标签、零附加效用，不继承攻击或法术加值。投射物的母箭、子箭或直接法术命中使用各自声明的效用；词缀不自行猜测或复制倍率。

`definition()` 保留 `base_id`、名称、槽位、尺寸、属性、实际档位和词缀行等 UI 元数据，另给出 `added_sources` 数组。只有四类新词缀生成来源记录，旧词缀不伪装为附加伤害：

```json
{
  "item_id": "gear_000001",
  "affix_id": "attack_added_fire",
  "stat": "attack_added_fire",
  "scope": "attack",
  "damage_type": "fire",
  "value": 4.0
}
```

每条恰好六个字段，`value` 为浮点运行时点数。这里 `scope=attack|spell` 是**事件来源作用域**，与目录元数据的 `scope=equipped_character` 含义不同。来源用于追溯装备和词缀，不第二次添加伤害；来源与属性都从实例派生，不接受存档直接注入来源记录。没有新词缀时数组为空。

## 5. 严格保存与向后兼容

实例结构仍恰好五个字段：`id, base_id, rarity, item_level, affixes`。每条词缀仍恰好三个字段：`id, tier, value`。增加 `stats`、`stage`、`scope`、`damage_type`、`added_sources` 或伤害端点等字段都会拒绝。

- JSON 整数读回为浮点时，只接受有限、精确整数；拒绝布尔值、字符串数字、NaN、无穷大和非整数
- 校验物品等级、词缀档位、解锁门槛、掷值范围、重复家族、重复组、稀有度数量及底材资格
- 新词缀的阶段、角色作用域、命中标签、伤害类型和底材白名单采用明确允许集合；未知或不匹配的元数据失败关闭，不回退到通用伤害
- `validate_instance(value, allow_expanded=true)` 默认为完整目录；旧存档 v1–v5 使用 `false`，即使是无词缀的普通符木法器也不能伪装成旧版本内容
- v6 允许新目录；既有装备实例和掷值保留，不重掷，不改名，不重编号。v1–v5 原字节备份与迁移由保存层处理

## 6. 自动验收与冻结证据

专用 `tests/typed_affix_catalog_test.gd` 在隔离 XDG 目录运行，不读写玩家真实存档：

```sh
XDG_DATA_HOME=/tmp/godot-typed-catalog/data \
XDG_CONFIG_HOME=/tmp/godot-typed-catalog/config \
XDG_CACHE_HOME=/tmp/godot-typed-catalog/cache \
godot --headless --path . --script tests/typed_affix_catalog_test.gd
```

覆盖：

1. 等级 1 / 7 / 8 / 15 / 16 / 30 × 普通 / 魔法 / 稀有 × 每组 1,000 件，共 **18,000 件扩展样本**；所有 4 × 3 新词缀档、9 × 3 兼容旧词缀档及每种词缀条数可达
2. **12,000 件混合自然奖励样本**，验证 75/25 池比例、7 底材可达、原稀有度权重、旧底材无新家族，以及强制稀有度不变
3. 三种生成器的同种子确定性、准确池选择顺序和拒绝无效请求时 RNG 不变
4. 每个定点范围端点、所有样本 JSON 往返、完整实例结构、来源精度和深拷贝隔离
5. 所有旧底材 × 所有新家族的反例，以及未知阶段、类型、作用域、标签和白名单的失败关闭
6. 从冻结 v0.6.0 目录复制到临时工程后执行生成的 **432 件黄金样本**，逐件比对完整物品和每次生成后的 RNG 状态，并核对所有旧定义

黄金数据是 `tests/fixtures/typed_affix_legacy_rng.json`。冻结源 SHA-256：`3f0b5aedb83ffb6543001fbc12bcaeaa3db27b9421b8e93b8d5c2f2d63dbf7c9`；由 Godot 4.6.3 生成。使用种子 1、603031、9817264，各 144 次连续调用；循环六个等级边界，每六次切换自动 / 普通 / 魔法 / 稀有，保存完整实例及字符串形式的 64 位 RNG 状态。禁止改动冻结源以迁就新实现。

本专测不代替保存层、完整战斗和自然死亡奖励的集成测试；这些分别验证 v6 迁移、快照隔离、真实伤害和一次死亡一次奖励。

## 7. 明确未实现

没有局部武器伤害、每次命中的最小 / 最大伤害随机区间、伤害转换、暴击、持续伤害、异常系统、通货制作或完整 PoE 词缀引擎。新底材和四家族都是原创小规模内容，不意味着研究目录整体可执行。
