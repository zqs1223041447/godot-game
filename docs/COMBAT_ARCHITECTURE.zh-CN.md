# 投射物生命周期与分类型伤害架构

Godot 原型实现说明与扩展约定

版本 1.0 · 2026 年 10 月 2 日

## 1 先把三个问题拆开

这份说明以龙卷射击为贯穿案例，解释怎样让技能、装备词缀、投射物行为和伤害计算各自负责清楚的一件事。目标是把组合规则写成可以追踪、测试和扩展的系统，而不是给每个新技能追加一段独立的伤害逻辑。文中的规则是本项目的原型约定，不是对其他游戏规则的精确复刻。

**第一层是技能配方。** 一次施放生成多少母弹、母弹怎样分裂、每种效果用哪份基础伤害，由配方声明。龙卷射击默认发射 3 枚母弹，每枚分裂成 3 枚子弹；增加投射物数量改变母弹数 n，子弹总数随之成为 3n。

**第二层是载体与生命周期。** 投射物负责位置、速度、射程、寿命、穿透、阶段与命中账本。它回答“东西怎样移动”和“何时发生事件”，不能仅凭载体是箭，就把此后所有效果也算成投射物伤害。

**第三层是伤害事件。** 一次命中或爆炸产生独立伤害包，包含基础伤害分量和本次事件的标签。伤害解析器据此挑选词缀，再按目标当下的减伤结算。爆炸可以由箭触发，但不因此获得 projectile 标签。

### 当前代码的分工

| 模块 | 当前职责 | 不应承担的职责 |
| --- | --- | --- |
| CombatData | 配方、进攻快照、词缀规范化、伤害包构建 | 移动碰撞、扣血、界面 |
| ProjectileRuntime | 生命周期、扫掠碰撞、阶段切换、事件与身份 | 根据当前装备临时重算旧弹伤害 |
| DamageResolver | 分量过滤、增伤乘区、实时防御、结算明细 | 分裂、返还、生成爆炸载体 |
| 游戏集成层 | 施放入口、目标状态、消费事件、扣血与表现 | 复制一套不同的伤害公式 |

**已经实现的范围：** 分类型直接伤害、词缀过滤、施放快照、龙卷母子弹、返还与自然结束爆炸、确定性分段扫掠、事件追踪及数量限制。**扩展约定而非已实现功能：** 伤害转换、暴击、持续伤害、持续追踪，以及通用图形化技能编辑器。

阅读顺序：第 2 至 5 节回答分类和生命周期；第 6 至 7 节说明数值；第 8 至 10 节说明工程边界；第 11 至 12 节用于验收与继续开发。

## 2 分类要描述不同维度

“这个技能是投射物技能”和“这一次伤害是投射物伤害”是不同信息。分类应允许组合，但不能互相替代。技能的界面标签供筛选与说明；伤害计算只读取本次伤害包明确声明的标签和分量。

### 四个需要独立保存的维度

| 维度 | 示例 | 用途 |
| --- | --- | --- |
| 来源身份 | 技能、施放、母弹、子弹、装备效果 | 追踪归属、限制次数、回放诊断 |
| 载体形态 | 移动投射物、瞬时圆形范围 | 移动、碰撞、范围查询 |
| 事件标签 | hit、attack、spell、secondary、projectile、area | 判断词缀是否适用于这次伤害 |
| 伤害类型 | physical、fire、cold、lightning、chaos | 按分量增伤与目标防御 |

attack、spell、secondary 是事件来源类别；projectile、area 是伤害交付方式；physical 等是伤害分量的类型。它们不能塞进一个互斥枚举。例如，母弹的一次命中同时是 hit、attack、projectile，并包含物理和火焰两种分量。

### 龙卷射击的三份伤害事件

- 母弹命中：标签为 hit / attack / projectile，基础伤害为 60% 物理、40% 火焰
- 子弹命中：标签相同，先使用子弹系数 0.7，再分成 60% 物理、40% 火焰
- 自然结束爆炸：标签为 hit / area / secondary / explosion，基础伤害为施放快照基础值的 0.9 倍，全部为火焰

爆炸的 secondary 分类是当前原型明确选择的规则。因此，未来 attack 或 spell 限定增伤不应自动作用于它。若以后设计一个“法术爆炸”，应修改那份爆炸配方的标签，不应给所有爆炸强行继承触发技能的界面标签。

### 装备词缀到底匹配什么

“全局伤害提高”匹配所有伤害事件的所有分量；“投射物伤害提高”要求事件含 projectile；“元素伤害提高”只匹配 fire、cold、lightning 分量；“范围伤害提高”要求事件含 area。物理和混沌不属于这里的元素集合。

一个词缀可以同时要求多个标签、限制伤害类型、限制技能 ID。所有要求都满足才适用。空标签集合表示不限交付方式，空类型集合表示不限伤害类型。这比直接检查“是不是龙卷箭”更可复用，也便于未来增加“某技能的火焰投射物伤害”等窄范围词缀。

## 3 声明式配方与施放快照

### 当前龙卷配方

| 参数 | 母弹 | 子弹 | 爆炸 |
| --- | --- | --- | --- |
| 数量 | n 默认 3，上限 9 | 每母弹固定 3 | 每合格自然结束最多 1 次 |
| 速度 | 420 | 260 | 不移动 |
| 外飞射程 | 150 | 150 | 半径 76 |
| 独立寿命 | 0.9 秒 | 1.7 秒 | 瞬时结算 |
| 基础伤害系数 | 1.0 | 0.7 | 0.9 |
| 基础类型比例 | 物理 60% / 火焰 40% | 物理 60% / 火焰 40% | 火焰 100% |
| 穿透 | 无限 | 无限 | 独立范围去重 |

数量公式为 n = clamp(3 + projectile_count, 1, 9)。提供 +2 投射物的装备把 3 枚母弹变成 5 枚，成功分裂后得到 15 枚子弹；这个词缀不把每一组的 3 枚也变成 5 枚。

有效鼠标方向仍优先。自动瞄准的最近目标与角色重合、不能给出方向时，保留角色原朝向；原朝向也为零才取向右。这一步发生在整组扇形展开和19单位发射偏移之前，普通飞弹、冰霜和蚀影也复用它；不改变单枚载体的原伤害／碰撞规则。见[重合瞄准修复](AIM_OVERLAP_FIX.zh-CN.md)。

母弹按瞄准方向在扇形内展开，相邻方向差为 0.16 弧度。每枚母弹抵达射程时，以该母弹的前进方向为起始方向，生成间隔 120 度的 3 枚子弹。它们在分裂点生成，不瞬移回玩家位置。

### 快照是一次施放的不可变输入

施放时固定进攻数值、规范化词缀、投射物数量和已授予效果，并深拷贝 tornado_recipe 与 explosion_recipe。子弹读取冻结配方中的速度、射程、寿命和系数，爆炸读取冻结的系数与半径。母弹和其后生成的子弹共享这次施放的数值语义，各对象保存独立的深拷贝，运行中不回读新装备来改变旧弹。

例如，母弹发射后卸下返还装备，已经施放的这批母弹及其子弹仍保留返还效果。反过来，发射后才穿上爆炸装备，也不会给这批旧弹补上爆炸。这样结果容易解释，也避免按分裂时刻或命中时刻换装获得额外收益。

**子弹继承进攻来源，但不继承母弹已经消耗的时间。** 子弹生成时 age 从 0 开始，lifetime 为自己的 1.7 秒；返还只切换方向与阶段，不刷新这 1.7 秒。

### 数据契约的最小集合

- 伤害包：base 按类型保存原始值，tags 保存本次事件标签，skill_id 保存技能来源
- 词缀：id、mode、value，以及 all_tags / damage_types / skills 过滤条件
- 投射物：身份链、位置速度、射程与年龄、状态、伤害包、快照、命中账本、已触发效果集合
- 运行时事件：时间、序号、投射物身份、阶段与位置，以及命中目标、结束原因或爆炸载荷

这些字段目前以 Dictionary 表达。类型化 Resource、编辑器校验与配方 schema 可以后续加入，不能因此声称现在已经具备完整内容工具链。

## 4 生命周期先解决再结束

母弹和子弹使用同一套载体状态，但不是同一套范围边界动作。母弹的分裂是技能结构行为；子弹的返还、爆炸是从装备授予的效果。结构行为必须先于泛用结束效果裁决。

### 母弹流程

施放 → 外飞 → 到达射程 → 分裂为 3 枚子弹 → 母弹以 split_consumed 结束。

分裂消耗母弹，不是一次自然结束，所以母弹不会在分裂点附带爆炸。若母弹在到达射程前已经寿命耗尽，则按自然寿命结束处理，而不是在死后补做分裂。当前默认速度与射程使母弹约在 0.357 秒抵达射程，早于 0.9 秒寿命。

### 子弹四种组合

| 子弹携带效果 | 到达射程时 | 此后结果 |
| --- | --- | --- |
| 无 | 自然结束 range_consumed | 安静移除 |
| 仅返还 | 截获范围结束，转入 returning | 同一寿命耗尽后安静移除 |
| 仅爆炸 | 自然结束 range_consumed | 在射程终点爆炸 |
| 返还与爆炸 | 先返还，不发出最终自然结束 | 原寿命耗尽，在最终位置爆炸 |

**自然结束只代表载体真正走完生命周期。** 射程到达本身是一个可被结构行为或返还截获的边界，不应先广播“已结束”，再尝试把同一枚弹复活。

自然结束的两个原因是 range_consumed 和 lifetime_expired。代码将自然结束命名为 flight_ended，由 explode_on_flight_end 监听；返还则由 return_on_range 监听 range_reached。爆炸不监听任意删除。碰撞耗尽、分裂消耗、重开清场、安全取消和预算取消都不能伪装成自然结束。

### 返还的精确定义

返还开始时读取玩家当前中心，只计算一次从子弹当前位置指向该中心的方向。之后按该方向直线飞行；穿过这个中心时不停下、不消失、不再次瞄准，直到同一份子弹寿命耗尽。玩家随后移动不会使它持续转弯。

返还每枚投射物最多触发一次，returning 阶段不再受外飞射程限制。若切换时子弹恰好位于玩家中心，则使用原速度的反方向作为退化方向，避免零向量产生不确定行为。

子弹约在 150 / 260 = 0.577 秒开始返还，剩余约 1.123 秒，返还段还能飞约 292 个距离单位。能否实际经过玩家，取决于返还开始时的距离与剩余寿命；“瞄向中心”不承诺一定有时间到达中心。

## 5 同一帧发生多件事时怎样裁决

只在帧末检查距离会产生越过射程后的幽灵命中，也会让低帧率子弹晚一帧出生。运行时应把一帧拆成若干连续小段，每段最多走到最近的语义边界。

### 一段移动的顺序

1. 求本帧剩余时间、剩余寿命，以及外飞阶段抵达射程所需时间
2. 取最短值作为本段时间，得到真实移动线段
3. 在线段上扫掠目标圆，按首次接触时间排序；同时刻按目标稳定 ID 排序
4. 逐个产生合法命中，消耗有限穿透；被碰撞消耗则立即停在接触点
5. 若仍存活，按寿命、范围、分裂或返还的边界优先级处理
6. 有剩余帧时间则继续推进；新生子弹也获得出生后的剩余时间

所有投射物的边界按时间统一调度，避免数组里排在前面的对象提前释放未来的容量；同刻再按边界优先级和载体 ID 裁决。这是确定性的事件语义，不等于已经实现跨平台锁步网络同步。浮点、输入采样、目标运动与随机数仍需要另外的同步契约。游戏世界按固定 60 Hz 推进，累计补帧时间最多 0.25 秒；严重卡顿会丢弃超出的追赶时间。每段扫掠使用本次 advance 的目标位置，尚不是双向连续刚体碰撞。

### 寿命与射程同刻时寿命优先

当射程与寿命恰好同时到达，寿命获胜：不分裂、不返还，以 lifetime_expired 自然结束。恰好处于寿命终点的碰撞不再算作命中；终点前已经发生的接触仍有效。

只有射程严格早于寿命时，普通射程终点接触才可以先结算，再执行分裂、返还或范围自然结束。这避免“同一箭已经到期，却又打一下、分裂、返还、爆炸”的多次竞争。实现允许极小浮点容差，测试必须固定边界期望。

### 命中去重以投射物与阶段为单位

账本键由阶段和目标 ID 组成；投射物本身拥有自己的账本。一枚子弹外飞阶段对同一目标最多命中一次，返还阶段可以再命中一次。返还重新经过已命中目标不会每一帧重复扣血。

兄弟子弹互不共享这个账本，因此允许多枚子弹击中同一目标，也就是本原型允许的“霰弹命中”。每次爆炸另外做自己的范围去重：同一次爆炸对目标最多一次，但不因为箭体已经命中过该目标而禁止爆炸命中。

龙卷母子弹的无限穿透保证碰到敌人后仍能完成预定生命周期。普通基础射击仍消耗其有限穿透，不能因为龙卷需要返还就把所有投射物改成无限穿透。

## 6 伤害公式按分量计算

每次伤害都从当前效果的原始伤害包出发。先按事件标签和分量类型挑选适用词缀，再累加 increased，随后逐项乘 more，最后读取目标当前防御。只在显示时取整，不能在中间每一步截断。

对类型 t 的一个分量，当前结算关系是：

**最终分量 = 原始分量 × max(0, 1 + 适用 increased 之和) × 所有适用 more 因子的乘积 × (1 - 当前类型减伤)**

词缀值使用小数：20% 写成 0.20；一条 10% more 的因子是 1.10。所有适用的 increased 共用该分量的一个加法桶，不能把全局、投射物、元素各自乘一次。不同 more 条目则独立相乘。解析器已支持 more；当前装备快照构造器只生成四种 increased 条目，以下 more 算例属于解析器能力演示。

### 同一原始伤害的对照算例

为了单独看清标签作用，假设两份独立事件都以 100 物理 + 100 火焰为原始值。一份有 projectile 标签，一份是无 projectile 的范围爆炸。装备提供全局 increased 20%、投射物 increased 50%、元素 increased 30%，目标无减伤。

| 事件与分量 | 命中的 increased | 算式 | 结果 |
| --- | --- | --- | --- |
| 箭体物理 | 全局 20% + 投射物 50% | 100 × 1.70 | 170 |
| 箭体火焰 | 全局 20% + 投射物 50% + 元素 30% | 100 × 2.00 | 200 |
| 对照爆炸物理 | 全局 20% | 100 × 1.20 | 120 |
| 对照爆炸火焰 | 全局 20% + 元素 30% | 100 × 1.50 | 150 |

箭体总伤害为 370，对照爆炸为 270。这里的混合类型爆炸只是公式对照，不是当前龙卷爆炸配方。若两者再共同获得 10% more 和 20% more，则分别为 370 × 1.1 × 1.2 = 488.4，以及 270 × 1.1 × 1.2 = 356.4。

### 不能把已经结算的箭伤拿来爆炸

如果把“箭体结算结果 × 爆炸系数”当成爆炸原始值，投射物增伤已经污染了爆炸，随后再套全局或元素词缀还可能重复加成。正确做法是由爆炸配方、施放时基础值和爆炸系数重新构造原始伤害包，再独立走解析器。

当前防御是按类型的简单百分比减伤，范围被限制在 -100% 至 90%。这是原型规则，负值代表易伤；并没有实现护甲曲线、穿透、抗性上限装备或某款游戏的完整防御系统。

## 7 把公式放回真实龙卷配方

设施放快照的 base_damage 为 100，仍使用全局 increased 20%、投射物 increased 50%、元素 increased 30%。不加额外 more，目标各类型减伤为零。

| 事件 | 原始物理 | 原始火焰 | 增伤后物理 | 增伤后火焰 | 合计 |
| --- | --- | --- | --- | --- | --- |
| 母弹命中 | 60 | 40 | 60 × 1.7 = 102 | 40 × 2 = 80 | 182 |
| 子弹命中 | 42 | 28 | 42 × 1.7 = 71.4 | 28 × 2 = 56 | 127.4 |
| 自然结束爆炸 | 0 | 90 | 0 | 90 × 1.5 = 135 | 135 |

子弹的原始总量为 100 × 0.7 = 70；爆炸的原始总量为 100 × 0.9 = 90。爆炸既不从母弹的 182 开始，也不从子弹的 127.4 开始；0.9 不是施加到子弹 0.7 之后的又一层系数。

若目标命中时物理减伤为 25%、火焰减伤为 40%，母弹实际伤害为 102 × 0.75 + 80 × 0.6 = 124.5；子弹为 71.4 × 0.75 + 56 × 0.6 = 87.15；爆炸为 135 × 0.6 = 81。目标防御在每次命中时读取，因此同一次施放的前后命中可以因为目标状态变化而得到不同最终伤害。

### 算例与实际装备

上面固定的投射物 50% 是公式算例。当前棱光长弓实际提供基础伤害 +4、投射物提高 40% 和母弹数 +2；归航披风授予返还；终焰护符提供全局 20%、元素 30% 和结束爆炸。长弓的 +4 会提高爆炸基础值，只有它的 40% 投射物增伤不作用于爆炸。解析器支持 more 与目标分类型减伤，但当前装备尚不授予 more 或抗性。

### 哪些词缀会改变哪些数

- 提高 projectile increased：提高母弹和子弹命中；不提高自然结束爆炸
- 提高 elemental increased：只提高母子弹的火焰部分，并提高纯火焰爆炸
- 提高 global increased：作用于三类事件的全部现有分量
- 提高 area increased：作用于爆炸；不因箭能击中多个敌人就把箭体变成 area
- 增加投射物数量：改变可产生的事件数量，不直接改变每次命中的单发数值

### 数量与重复命中的平衡后果

默认 n = 3 最多生成 9 枚子弹；+2 后变成 15 枚；上限 n = 9 时为 27 枚。只要全部分裂成功，这部分子弹数量提升分别是 66.7% 和 200%，但实际总伤害仍受站位、射程、寿命、范围重叠和目标数量影响。

允许兄弟子弹同时命中、允许外飞与返还各命中一次，再叠加独立爆炸，会放大近距离与大体积目标的收益。不能用“面板单发伤害 × 固定弹数”直接宣称真实 DPS。后续平衡可调整子弹系数、扇形、半径、寿命或同一目标的跨弹限制；若改为禁止霰弹命中，必须同时改变账本作用域和验收测试，而不是暗中改一条数值。

## 8 事件身份与结算追踪

每次施放、每个载体和每次结算，都应能沿“谁触发谁”的来源链回到最初配方。

### 运行时的身份链

| 字段 | 含义 |
| --- | --- |
| cast_id | 同一次施放的所有母弹、子弹共享 |
| projectile_id | 当前载体唯一身份 |
| parent_id | 直接生成自己的母弹；母弹为 0 |
| root_id | 自己所属母弹分支的根；不是整个施放的共同 ID |
| generation | 母弹为 0，子弹为 1 |
| phase | outbound 或 returning 等当前阶段 |
| time / sequence | 帧内发生时间，以及同刻事件的稳定次序 |
| reason | 结束、拒绝或取消的具体原因 |

一次多母弹施放有多个 root_id，但只有一个 cast_id。未来要做“每次施放最多触发一次”必须使用 cast_id；要做“每个分裂分支一次”则用 root_id。把这两个字段混为一谈，会让 n 枚母弹的装备触发数量错误。

### 应能回答的调试问题

当玩家问“为什么这次没有爆炸”，追踪应先区分 split_consumed、hit_consumed、range_consumed、lifetime_expired 与清场取消，再看快照中是否授予效果、是否已经触发。不能只打印“投射物删除”。

解析器保留每个分量的原始值、increased 总量、more 乘积、防御前数值、减伤、最终值与已应用词缀 ID。结合事件标签，就能解释投射物增伤为何不作用于爆炸；当前不另外保存每条被排除词缀的拒绝说明。

### 在游戏中查看

按 F6 打开“战斗机制 · 龙卷实验”。预览是未计敌人防御的逐分量伤害，不是 DPS；下方显示真实事件和近期伤害。“试装完整组合”会更换三个装备槽并把龙卷放入技能栏第 1 格。各开关实际穿戴或卸下装备并自动保存，不是临时模拟开关。

### 实际结算和表现解耦

运行时返回事件，游戏层按事件扣血、加状态、生成飘字和视觉特效。爆炸是一次瞬时范围伤害事件，不是偷偷生成一枚零速度投射物。否则它可能再次获得返还、分裂或结束爆炸，形成递归触发链。

事件按时间和序号整理后消费，目标已死亡时应在结算层尊重实时状态。视觉圆圈或特效寿命只控制显示，不能再次驱动伤害。当前生命周期追踪保留最近 96 条，伤害明细保留最近 32 条，靠 projectile_id 关联；这是有界调试记录，不是永久战斗回放。日志和明细不应被重新当成下一次伤害的原始输入。

## 9 存档兼容与有界运行

### 构筑存档保存选择而非飞行状态

当前构筑存档应继续保存技能、装备、天赋等持久选择，再由这些选择重建数值与效果。场内正在飞行的投射物、命中账本、半途返还方向和调试事件不是构筑数据，不应混入原有存档。

新增数值字段使用缺省值：缺少 increased 字段视为 0，缺少额外投射物数量视为 0，缺少已授予效果视为空。当前保存格式为 v3：v1 / v2 迁移会一次性补发三件机制装备，但保留原有已装备物品和技能选择，效果仍需实际穿戴才启用。首次写回前，以 .v1-backup.json 或 .v2-backup.json 后缀保留原始内容；v1 旧天赋点按既有规则返还，v2 天赋与珠宝保留。

如果未来要保存战斗中途状态，需要另外定义版本、随机数状态、施放快照、剩余寿命、身份分配器和账本的序列化；那是新的功能，当前文档不将构筑存档兼容等同于战斗回放恢复。

### 数量预算是玩法规则的一部分

当前活跃投射物上限为 180，龙卷母弹数上限为 9，分裂世代上限为 1。一次施放的 n 枚母弹按全有或全无方式准入；预算不足时不悄悄从 5 枚改成 2 枚，游戏入口还会退回这次龙卷的法力并取消冷却。

一次分裂同样要求完整容纳 3 枚子弹，计算时先释放母弹占用的 1 个位置。预算或世代不允许时，整组分裂拒绝，并以明确取消原因结束母弹；不生成残缺的 1 或 2 枚子弹，也不把拒绝误判成自然爆炸。

这些上限保证对象数量与效果链有界，但不代表任何敌人数或帧率下都已达到性能目标。当前每段扫掠遍历目标，成本随活跃弹数与目标数增长；下一步优化可使用空间网格筛选候选目标，同时保留接触时间与稳定 ID 排序。

### 离屏与清场必须分开

离开可视范围不是自然死亡，不能在屏幕边缘静默删掉仍在返还或等待寿命结束的子弹。表现层可以裁剪绘制，逻辑层继续推进其生命周期。

重开、退出战斗和显式安全取消则是管理行为：清理对象但不触发战斗爆炸。新增保险阈值时必须给出可追踪的取消原因，不能统一调用“自然结束”。这既避免重开时满屏爆炸，也避免玩家利用清场触发额外伤害。

**验证边界：** Linux 图形界面已核验 3 母弹 → 9 子弹 → 9 次返还 → 9 次寿命结束爆炸，以及装备切换和伤害明细。Windows 导出包的原生启动尚未在 Windows 环境核验。

## 10 为后续机制预留明确接口

这一节是未来设计契约，不是当前功能清单。扩展前先确定数据来源、执行时机、重复触发限制和测试期望，再接入现有层次。

### 伤害转换

转换应在原始分量阶段进行，早于 increased、more 和目标防御。每个分量需要保留来源类型、转换路径与转换比例，并明确原类型与目标类型增伤如何适用。必须防止循环转换、同一份基础值被转换两次或总量无意增长。

当前 60% 物理 + 40% 火焰是配方直接声明的混合基础伤害，不是已经实现“物理转火”。未来即使显示数值相同，转换来源规则也可能不同，不能借现有比例假装完成转换系统。

### 暴击与持续伤害

暴击需要约定判定作用域：每次施放、每枚投射物，还是每次命中；还要定义子弹和爆炸是否独立判定。进攻参数可随施放快照，但随机结果的生成时点与 seed 身份必须明确，避免仅因帧率变化而改变结果。

持续伤害需要独立的周期实例与 tick 调度，并区分 hit 与 dot 标签。它不能假装成同一枚 projectile 每帧碰撞，也不能未经设计从命中结算结果复制伤害，否则会重复继承不适用的命中、暴击或投射物加成。

### 追踪与新的移动方式

当前返还是一段一次取向的直线。持续追踪应另建 steering 策略，声明目标取得、转向速度、目标失效后的行为和更新时间。回旋、弹跳、链击也应分别定义边界动作与命中账本，不应把所有行为塞进 returning 状态的一个布尔开关。

### 从数据驱动原型走向通用效果系统

当前配方与效果描述已分离，但运行时仍显式认识分裂、返还与爆炸。它是小而可检验的组合基础，不是任意效果都能靠 JSON 自动运行的解释器。继续扩展时，可将边界动作注册为处理器：输入载体与事件，输出状态变化、伤害事件或生成请求。

每个处理器还应声明监听事件、适用对象、次数限制、优先级、生成预算与递归深度。priority 字段本身不能代替已验证的调度器；引入通用排序后必须让“结构分裂先于泛用结束效果”和“寿命同刻优先”等规则继续成立。

## 11 验收矩阵

验收应同时检查数值、事件顺序、对象数量与否定条件。只看屏幕上“有箭、有爆炸”不足以证明底层组合正确。

| 场景 | 必须得到的结果 |
| --- | --- |
| 默认龙卷 | 3 母弹，各生成 3 子弹，总共 9 子弹 |
| +2 投射物 | 5 母弹，各生成 3 子弹，总共 15 子弹 |
| 数量超上限 | 母弹最多 9，完整分裂最多 27 子弹 |
| 分裂瞬间 | 母弹 split_consumed，不因分裂产生爆炸 |
| 无装备效果 | 子弹在射程终点安静自然结束 |
| 仅爆炸 | 子弹射程耗尽立即爆炸，不能等一个已不存在的载体到期 |
| 仅返还 | 射程边界返还，原寿命耗尽后安静结束 |
| 返还与爆炸 | 射程边界不爆；穿过初次瞄准中心继续飞；寿命耗尽爆炸 |
| 返还后玩家移动 | 子弹保持已采样方向，不持续追踪 |
| 施放后换装 | 已飞出的母弹及其子弹沿用旧进攻快照和效果列表 |
| 母子寿命 | 子弹从出生重新计时；返还不刷新子弹寿命 |
| 射程寿命同刻 | 寿命获胜；不分裂、不返还，不记寿命终点命中 |
| 射程早于寿命 | 射程终点接触可先命中，再执行边界动作 |
| 一个目标反复重叠 | 同投射物同阶段只命中一次；返还可再一次 |
| 多枚兄弟子弹 | 可以分别命中同目标；爆炸使用独立去重 |
| 大 delta 跨分裂 | 子弹获得出生后的剩余帧时间，不晚一帧移动 |
| 同刻多个接触 | 按稳定目标 ID 裁决，不依赖目标数组顺序 |
| 普通弹穿透耗尽 | hit_consumed；不借自然结束爆炸 |
| 清场或安全取消 | 无爆炸；有明确取消原因 |
| 数量预算不足 | 整次母弹施放或整组 3 子弹拒绝，不残缺生成 |
| 离屏返还子弹 | 继续模拟至真实结束；不因离屏提前消失 |
| 公式对照 | 箭 370、对照爆炸 270；加 more 后 488.4、356.4 |
| 真实配方 base 100 | 母弹 182、子弹 127.4、纯火爆炸 135 |
| 目标防御变化 | 后续命中读取新防御，不改写进攻快照 |

自动化测试应使用固定位置、固定 delta 与固定目标 ID，并对事件类型、结束原因、时间、身份链和伤害明细作断言。测试容差只用于浮点误差，不能用宽松范围掩盖重复命中或错误乘区。

combat_integration_test 验证场景集成；既有 build_test、passive_jewel_test、smoke_test 负责构筑与玩法回归。配方、装备文案与测试需要同步更新。

### 新增一个技能的建议顺序

1. 定义技能产生哪些载体与哪些独立伤害效果，不从界面标签猜伤害分类
2. 为每份伤害写出原始分量、系数和本地标签，并给出一个可手算例子
3. 选择已有移动与边界动作；确需新动作时，为其明确事件时机与优先级
4. 定义快照字段、身份归属、次数限制和命中去重范围
5. 定义预算不足、目标死亡、同刻到期和清场时的行为
6. 接入共同解析器与追踪明细，再完成矩阵测试和实际游玩观察

### 三个容易走回老路的实现方式

**按技能名称分支结算。** 若解析器需要“龙卷则减半、爆炸则再乘”的长分支，应先补足配方和标签输入，让解析器继续只关心分量与匹配规则。

**把删除当作自然结束。** 射程结束、寿命结束、分裂消耗和清场取消是不同原因。先裁决原因与事件，再移除载体。

**把一次结果当作另一次输入。** 已结算箭伤和扣血值不是爆炸或持续伤害天然应继承的基础值。新效果必须有独立可解释的原始来源。

### 架构的完成标准

装备说明授予的行为或词缀，伤害说明本地标签与原始分量，载体说明事件如何产生。保持这些边界，复杂玩法才会由清楚的规则组合出来，而不是依赖越来越大的技能特殊判断。
