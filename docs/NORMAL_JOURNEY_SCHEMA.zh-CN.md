# 普通旅程存档合同（schema26）

本批只新增顶层必填 `journey`；源天赋可执行词汇仍是 schema25 的生命/法力偷取版本。新档和旧档迁移均从零旅程开始，不推测历史击杀，不赠送宝石、药剂或碎片。

## 固定结构

`journey` 必须且只能包含以下七项：

| 字段 | 约束 |
| --- | --- |
| `normal_root_kills` | 真整数，0–1,000,000,000 |
| `best_tiers` | 只有 `old_garden` 和 `broken_ruins`，各为0–3真整数 |
| `next_run_id` | 1–1,000,000,000真整数；默认1 |
| `active_run` | 空字典，或下述固定进行中记录 |
| `pending_map_reward` | 空字典，或下述固定待领记录 |
| `claimed_gems` | 0至 `floor(normal_root_kills / 30)` 的真整数 |
| `claimed_flasks` | 0至 `floor(normal_root_kills / 60)` 的真整数 |

除 `next_run_id` 默认1外，计数和最高层级默认0，进行中/待领奖励记录默认空。两个记录不能同时存在。状态不包含怪物、首领生命、掉落随机流、计时器、运行场景或战斗恢复实例。

进行中记录只有 `run_id, map_id, tier, normal_ids, special_ids, fee_paid`。序号必须为正且小于下一序号；层级1–3且不高于该图最高完成层级+1；词缀必须经过当前普通地图编译器验证并按规范顺序保存；已付成本必须等于该层级成本。

待领记录只有 `run_id, map_id, tier, shards`。序号必须为正且小于下一序号；地图必须已解锁并完成该层级；碎片是该层级基础奖励至基础奖励+4的真整数。待领记录不保存词缀，因此加载时检验合法奖励区间；首次完成则严格从进行中记录重新编译完整词缀奖励。

JSON 解码只把有限、整值、合法范围的数值转为整数；布尔值、字符串、任意强转、NaN/无穷和小数均拒绝。纯 `reason()` 不做转换，要求真整数。所有字段名称和词缀身份都必须是真字符串。

## 无副作用的计划

`NormalJourneyState.empty/decode/reason/start/complete/abandon` 均不操作背包、货币或磁盘。失败返回 `{ok:false, reason, journey:{}}`；成功返回独立候选，调用方输入不变。

- `start(journey, profile)` 只接收普通地图编译器的完整规范配置；存在进行中记录或待领奖励时拒绝。验证解锁和剩余序号后，推进一次序号并保存进行中记录，另返回 `run_id` 和 `cost`
- `complete(journey, run_id)` 只匹配当前进行中序号一次；重新编译奖励，保留各图最高完成层级，清空进行中记录并生成待领记录，另返回碎片数 `reward`
- `abandon(journey, run_id)` 只清空匹配的进行中记录；不退款、不解锁、不回收序号

普通两图各有三层。旧庭波次1/4/8，断垣2/5/9；费用0/4/8，基础完成奖励4/8/12。每个普通词缀+1奖励、特殊词缀+2奖励，最多额外4。旧测试地图配置不经旅程计划，不改变其既有合同。

`next_run_id = 1,000,000,000` 是耗尽状态：可加载、结算或放弃最后一场，但不能再开始；最后可分配序号为999,999,999。

## 稳定里程碑身份

`gem_definition(ordinal)` 从代码中冻结、按字典序列出的26个真实宝石定义选择，不在调用时枚举新目录。每个正序号使用独立 `RandomNumberGenerator`，种子 `0x47454D31 XOR ordinal`；无共享 RNG 消耗。以后增加目录条目也不能改变已经欠付的奖励。

`flask_definition(ordinal)` 复用 `FlaskCatalog.reward_definition(ordinal * 60)`，奇数生命、偶数魔力。非正序号和超过击杀上限可达到的序号返回空身份。这两个函数只确定身份，不领取、不分配UID、不推进已领计数。

## 严格迁移和写盘边界

`decode_v25/reason_v25` 保留原11字段顶层 envelope；声称25却注入 `journey` 的文件在任何备份或写盘之前拒绝。`SourceLeechMigration` 固定输出25并调用 `reason_v25`，旧链按原次序执行，最后只包一层25→26迁移。

25→26先按旧25全部校验，再仅更改版本并用字符串键新增空旅程。物品实例、UID、位置、技能、快捷键、等级经验、源树分配、制作修订和迁移账本逐项保留。最后仍由完整26规则校验。

Store继续使用原始字节备份、原子写入和外部改写保护。备份冲突/失败、主文件写入失败、备份后外部改写、未知未来版本或非法候选均不公布新内存。整个旧版链只备份原版本字节、只提交一次；匹配的旧字节备份允许安全重试。当前26加载不重写。

真实未修改的 v0.40.0 / `8e5f4fb3612077e31f2744450d5036972c73b9cf` 导出了默认25和已分配真实偷取节点 `36704` 的25夹具。后者还含不同UID、序号和两种修订号，避免仅测默认数据。夹具保留开头空白和CRLF，并以目录内 `.gitattributes` 禁止Git文本归一化；哈希和来源记录在 `tests/fixtures/v041_journey/manifest.json`。
