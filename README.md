# godot游戏仓 · 裂隙试炼

以 **构筑与技能组合** 为核心的俯视平面竞技场。基于 **Godot 4.6.3 标准版 / GDScript**，目标平台 **Windows x86_64**。

## v0.6.0：技能辅助链接与可辨识战斗反馈

- **每技能两个辅助槽**：K 为龙卷、飞弹、冰霜配置辅助；辅助绑定技能本身，交换快捷栏位置不丢失、不重置已有冷却
- **两种原创取舍**：散束辅助增加 2 枚初始投射物，投射物击中伤害总降 20%，耗魔 ×1.30；凝束辅助令投射物击中伤害总增 25%，耗魔 ×1.20。两者组合耗魔 ×1.56
- **数量和作用域明确**：长弓加散束龙卷为 7 母箭 → 21 子箭；不重复增加每枚母箭的子箭数。辅助不改变独立爆炸、普攻或其他技能
- **一份编译结果**：数量、伤害快照、魔力和冷却供执行/预览共同使用；不足魔力或完整弹幕容量时，不扣费、不部分发射、不播放施放反馈
- **精确预览与安全持久化**：K 和快捷栏展示两位小数耗魔、实际数量及不兼容原因；v5 存档支持 v1–v4 备份迁移，旧装备和掷值保留。飞行中变更辅助或装备只影响以后施放
- **战斗反馈分型**：新星径向印记、结界六角盾、陨星落点、冲刺轨迹、连锁连接线、命中/受伤/减速标记与投射物生命周期反馈；低特效仍保留连锁路径和关键边界
- **有界表现层**：独立反馈池最多 96 个、每个最多 0.65 秒；不修改碰撞、数值、存档或随机序列

30 秒体验：F6 → 试装完整组合 → K → 选择龙卷所在槽 → 添加两种辅助。可看到 7 枚母箭、28.08 魔力；关面板按 1，再用 F6 对照箭体与独立爆炸的结算。

辅助本版全部可用，不含实体宝石、插槽连线经济、等级或品质；也没有扩展暴击、DoT 或局部武器结算。完整契约见[技能辅助设计](docs/SKILL_SUPPORTS.zh-CN.md)。

## v0.5.0：随机装备与二维视觉基础

- **真实随机装备**：6 个原创底材、12 类可执行词缀、各 3 档。普通 / 魔法 / 稀有物品拥有独立实例、物品等级、前后缀和掷值；原有 9 件示例与机制装备全部保留
- **有边界的投放**：原始怪每 8 次有效击杀尝试发放一件装备；稀有怪与首领原始怪必定尝试发放稀有装备。同一次死亡最多一件，后代和 F7 试验场不给奖励
- **真正的词缀作用域**：法术、火/冰/电、攻击元素与投射物提高分别匹配；独立爆炸不会继承投射物或攻击限定。普通攻速、移速、魔力恢复百分比在基础加值后结算，不误作每秒点数或技能冷却
- **可检查的详情**：I 查看物品等级、词缀类型、T1/T2/T3 与实际数值；本项目 T3 更高，属于原创编号。生成装备可以换装、拖放和确认丢弃，固定示例不会被丢弃
- **容量和存档保护**：领取前为所有已装备/已镶嵌物品预留回包空间；满仓不覆盖已有物品。存档升级至 v4，v1/v2/v3 在首次原路径覆盖前保留原字节备份
- **二维视觉基础**：原创兜帽角色、分物种怪物轮廓、稀有度符号、石砌场景与分层技能特效；渲染独立于战斗数据
- **显示选项**：Esc → 显示设置；UI 90/100/110%、字体 100/110/120%、三级特效、伤害数字与动态效果开关，独立保存在显示配置中
- **施放失败不扣费**：飞弹与冰霜也先检查整次弹幕容量，放不下时不消耗魔力或冷却

30 秒体验：常规挑战击败 8 个原始敌人 → 按 I 查看新装备 → 比较词缀并换装；Esc 可调整显示。想继续试组合，按 F6 一键装配原来的龙卷机制装备。

本版把装备研究接成一个小而完整的可玩闭环。1,200 条研究词缀不直接导入运行时，尚无制作、地面战利品、局部武器伤害、技能辅助宝石、暴击或完整异常系统。未来依赖与验收见[构筑路线](docs/BUILDCRAFT_ROADMAP.zh-CN.md)，实际支持边界见[装备执行契约](docs/EQUIPMENT_RUNTIME.zh-CN.md)和[原创目录](docs/EQUIPMENT_CATALOG.zh-CN.md)。显示验证与后续视觉路线见[视觉系统](docs/VISUAL_SYSTEM.zh-CN.md)。

## v0.4.0：怪物机制、共享天赋与 PoE 设计适配

- **五类怪物**：白 / 蓝 / 金进入普通波次；橙色只由关卡或特殊地图 Boss 上下文生成；黑色仅保留，不进入任何生成池。每五波出现原创“裂隙守卫”
- **可配置死亡分裂**：蓝色裂殖巡游体 → 2 只普通巡游体 + 1 只掠行体；金色孵化重壳体 → 2 只裂殖巡游体 → 6 只终端小怪。特殊 A 与普通 A 是不同状态模板
- **无无限递归**：内容加载拒绝生成图循环；一次性死亡账本、最多 3 代 / 每谱系 12 后代 / 每次 6 子怪、场上 55 怪与 64 待生成队列共同防护。场满 FIFO 等待，预算不足整组取消
- **奖励防刷**：只有原始怪提供经验、补给与珠宝进度；后代只计入击败总数。重复死亡、尸体清理、重置与玩家死亡都不会额外触发生成或掉落
- **共享天赋定义**：玩家与怪物引用稳定机制 ID，数值只存一份。支持的生命、伤害、攻速、移速、护盾与回复机制真实执行；怪物不支持的魔力 / 标签机制整包拒绝。版本修改自动作用于新怪物，不手工复制数值
- **PoE 天赋适配**：固定官方树源，保留本项目原创 181 节点与路径；用明确尺度与参考基础值重做本游戏平衡，加入已有执行器支持的全局 / 投射物 / 元素 / 范围“提高”词缀。天赋单独计算总预算，装备与珠宝不占该预算
- **普通装备词缀研究**：固定 PoE1 数据源，筛出 1,200 条普通显式词缀档、852 个底材、24 类装备和 36 项原创语义映射。此部分是研究参考，尚未实现完整随机装备/制作系统，也不打入游戏运行包
- **F7 怪物试验场**：查看五类、共享机制快照、生成规则与事件，重复演示 A → 2A + B；试验场不给成长奖励，随时恢复常规挑战

30 秒体验：按 **F7 → 进入 / 重置试验场 → 演示 A → 2A + B**，向下滚动查看三只第 1 代子怪与生成记录；按 Esc 继续战斗。

设计与证据：[怪物系统](docs/MONSTER_ARCHITECTURE.zh-CN.md) · [PoE 天赋适配与平衡](docs/POE_PASSIVE_ADAPTATION.zh-CN.md) · [普通装备词缀研究](docs/POE_AFFIX_REFERENCE.zh-CN.md)

## v0.3.0：投射物生命周期与伤害机制

这一版围绕底层组合规则重构战斗，并用“龙卷射击”验证机制，而非只增加技能数量。完整设计、伤害演算、扩展边界与验收场景见 [战斗底层设计](docs/COMBAT_ARCHITECTURE.zh-CN.md)。

- **载体与伤害分离**：母箭、子箭、直接法术和爆炸分别持有自己的伤害包与标签；爆炸不继承投射物增伤
- **自然结束先仲裁**：射程边界先判断分裂、返回，再决定是否自然结束；总寿命是不可延长的上限
- **龙卷组合**：默认 3 枚母箭，每枚分裂 3 枚径向子箭；棱光长弓增加到 5 枚母箭 / 15 枚子箭
- **归航披风**：子箭到射程后，取人物此刻中心方向返回一次，穿过中心继续直飞；不是持续追踪，不刷新寿命
- **终焰护符**：自然飞行结束触发独立火焰爆炸。仅爆炸装备在射程处爆炸；配合返回则在子箭出生 1.7 秒后爆炸
- **明确排除**：母箭被分裂消耗、普通箭碰撞耗尽、死亡、重置与容量取消均不触发自然结束爆炸
- **逐分量结算**：全局提高作用于全部伤害；投射物提高仅作用于箭；元素提高仅作用于火焰 / 冰冷 / 闪电。同一分量的“提高”相加，独立“更多”相乘
- **施放快照**：属性、效果和配方在施放时锁定；子箭、返回与爆炸继承同一快照。敌方抗性在实际命中时读取
- **可靠命中**：精确分段到射程 / 寿命边界，扫掠碰撞按距离先后结算；每枚箭每阶段每敌人一次，不同子箭与爆炸可分别命中
- **F6 机制面板**：实际穿脱三件机制装备、查看母箭 / 子箭 / 爆炸的公式拆解、最近真实伤害和生命周期记录

### 30 秒体验组合

1. 按 **F6**，点击 **试装完整组合**：龙卷进入槽 1，三件机制装备自动穿戴并保存
2. 关闭面板，按 **1** 释放：绿色母箭 → 青色子箭 → 紫色返回箭 → 橙色爆炸
3. 再按 **F6** 查看真实记录；独立开关返回、爆炸和长弓，比较行为与增伤

目前不含伤害转换、暴击、持续伤害、持续追踪、分叉/连锁投射物或任意用户脚本效果编辑器。`DamageResolver` 已支持独立“更多”与抗性参数，当前装备仅投放“提高”词缀，敌人默认抗性为零。这些是明确的扩展接口，不代表已有对应玩法。

## v0.2.0 功能：天赋星图、珠宝与格子背包

这一版把旧的五条天赋列表替换为可平移、缩放的连接式大型天赋树，并加入普通珠宝系统。图形、名称与节点布局为本项目原创；机制参考 PoE 的基础天赋槽与珠宝，不包含其资产或原始天赋布局。

### 天赋星图

- 181 个节点、360 条连线、六个属性主题分区；包含 24 个核心天赋、12 个珠宝槽与环路和跨区路线
- 起点免费激活；只能分配与现有已点路线相连的节点，每个节点消耗 1 点
- 新角色有 5 点，升级获得更多；最早的珠宝槽只需沿路线投入 3 点
- 退回单个节点必须保证剩余已点节点仍与起点连通；也可免费重置全树
- 退回珠宝槽或重置时，里面的珠宝会安全回到珠宝背包
- 选择节点查看属性和状态；滚轮缩放，拖动空白处或中键平移；工具栏可回到起点、缩放或总览
- 各种状态用形状、文字与颜色区分，已点路线为金色，可点邻接节点高亮

### 珠宝

- 三种原创基底；魔法珠宝最多 2 条词缀（1 前缀 + 1 后缀），稀有珠宝最多 4 条（2 前缀 + 2 后缀）
- 新角色有 3 颗固定示例珠宝；每轮战斗每击败 20 个敌人，自动获得 1 颗随机珠宝
- 在天赋星图中选择已激活的珠宝槽，再选珠宝镶嵌；可替换、取下及在槽位之间移动
- 珠宝的伤害、生命、魔力、护盾、攻速、移速与回复词缀立即影响真实战斗属性
- 每颗珠宝拥有独立标识，只能处在背包或一个槽位中；总藏品上限 64，满时不再发放奖励，已有珠宝不会被覆盖
- 可在珠宝详情中丢弃背包里的珠宝；需要再次确认，丢弃后不可恢复，已镶嵌珠宝不能直接丢弃
- 珠宝与天赋共同保存；打开任意构筑面板都会暂停战斗

本阶段仅实现基础魔法/稀有属性珠宝。尚未实现星团、永恒、半径、唯一珠宝或通货制作。

### 格子背包

- 12 × 8 格共享背包：武器占 1 × 3 格，护甲占 2 × 3 格，饰品和珠宝占 1 格
- 装备槽、背包与物品详情在同一界面；使用原创几何图标区分物品
- 拖动物品可自由摆放；拖到正确装备槽穿戴，已装备物品可拖回背包
- 重叠、越界和放错装备槽会被拒绝，不改变现有物品
- 点击物品查看词缀和尺寸；也可使用按钮穿戴/卸下，以及一键整理
- 取下珠宝、退回天赋槽及重置时统一回到背包；必要时自动整理空间，保留所有物品
- 背包布局随构筑保存；旧版拥有的装备会自动安置

### 已有玩法

- WASD / 方向键移动，平面竞技场，三种追击敌人与随时间增强的波次
- 自动锁敌射击、鼠标瞄准、穿透、减速、范围伤害、击退与连锁闪电
- 生命、魔力与能量护盾 HUD；护盾优先承伤，受击 4 秒后开始回复
- 8 种主动技能：龙卷、飞弹、冰霜、新星、冲刺、结界、陨星、闪电；通过面板配置 1—5 技能槽
- 9 件初始装备、武器 / 护甲 / 饰品槽，装备替换会立即更新属性
- 补给、伤害数字、暂停、死亡与重试、本地构筑成长存档
- 自带中文字体，不依赖 Windows 安装中文字体

这是未签名开发原型。原创二维图形由程序绘制，已有基础随机装备奖励；尚未加入最终角色动画、音效、刷图关卡、辅助技能宝石或联机。

## 快速开始

1. 解压 Windows 发布包，双击 `GodotGame.exe`
2. 按 **T** 打开天赋星图，沿任意亮起路线点出珠宝槽；在右侧选择一颗初始珠宝并镶嵌
3. 关闭面板开始战斗，按 **1—5** 使用技能；击杀升级获取更多天赋点，20 次击杀获得珠宝

不需要安装 Godot。不要绕过系统安全警告；也可以在 Godot 编辑器中打开源工程运行。Windows 可执行文件已导出并检查格式，但本环境没有 Windows / Wine，**尚未完成 Windows 实机启动验证**。

## 存档与旧版升级

Windows 默认位置：`%APPDATA%\Godot\app_userdata\godot游戏仓\build_save.json`。

- 保存装备、技能、等级、经验、天赋路线、珠宝实例与镶嵌位置；不保存当前战斗状态
- v0.1 存档可读取：保留装备、技能与成长，把旧天赋的全部已花点数退回，并发放基础珠宝
- 首次保存迁移结果前自动保留原始 `build_save.json.v1-backup.json`；备份失败会停止写入并保留旧文件
- v0.3 使用存档格式 v3；v1 / v2 均可升级。v2 保留原构筑，补发三件机制装备，不强制替换已有装备与技能
- 升级覆盖前保留原始 `.v1-backup.json` 或 `.v2-backup.json`；冲突或备份失败会停止覆盖
- v0.5 使用存档格式 v4；v3 迁移保留原装备、天赋、技能和珠宝，新增随机装备实例表。原字节备份为 `.v3-backup.json`；错误实例拒绝整份加载
- v0.6 使用存档格式 v5，按技能 ID 保存辅助；v4 升级在首次原路径覆盖前保存 `.v4-backup.json`，不改原装备掷值
- 新存档不能由旧版程序读取；如需回退，可在备份现有存档后恢复对应旧版备份
- 读取时验证点数、图连通性、珠宝词缀和唯一位置，拒绝损坏或越界数据，避免部分加载
- 写入使用临时文件后替换；构筑变化后与战斗中定期自动保存，存档不进入 Git

## 开发运行

安装 [Godot 4.6.3 标准版](https://godotengine.org/download/archive/4.6.3-stable/)，导入 `project.godot` 后按 F5，或：

```sh
godot --path .
```

使用 Compatibility 渲染器，逻辑分辨率 1280 × 720；窗口缩放保持宽高比。

### 验证

```sh
bash tools/validate.sh
```

可用 `GODOT_BIN` 指定引擎。脚本隔离 Linux 设置、缓存和存档，并检查引擎输出中的脚本错误。

验证包含 95,000 个随机装备样本、实例/词缀/掉落/容量/旧版迁移、技能辅助编译/真实施放/UI、600秒组合模拟压力、独立视觉反馈和显示设置，以及项目导入、装备与技能模型、树路径与连通性、珠宝事务与词缀、v1 / v2 迁移与 v3 往返、畸形存档拒绝、共享机制/来源校准/240条同点数路径与507个怪物组合、死亡生成图/谱系/奖励/容量边界、投射物生命周期/伤害分量/时序/快照、真实战斗/UI 集成以及无界面启动。发布前另做云端 Linux 图形交互检查；无界面与 Linux 检查均不等同于 Windows 实机验证。详见 `CHANGELOG.md`。

### Windows 导出

安装与引擎匹配的 **4.6.3** 官方导出模板：

```sh
mkdir -p builds/windows
godot --headless --path . --export-release "Windows Desktop" builds/windows/GodotGame.exe
```

PCK 嵌入 EXE，未签名，不修改 Windows 资源。可运行 `python tools/verify_windows_pack.py builds/windows/GodotGame.exe` 验证 PE 架构与全部内嵌资源哈希。模板来自 [Godot 官方发布](https://github.com/godotengine/godot-builds/releases/tag/4.6.3-stable)。构建产物放在忽略目录 `builds/`。

### 字体

`assets/fonts/arena_sans.otf` 是 Noto Sans CJK SC 的 UI 文本子集，家族名改为 Arena Sans SC，按 SIL OFL 1.1 分发。许可证见 `assets/fonts/OFL-NotoSansCJK.txt`。

新增中文文本后可重建子集（运行游戏无需 Python）：

```sh
python tools/subset_font.py /path/to/NotoSansCJK-Regular.ttc
```
